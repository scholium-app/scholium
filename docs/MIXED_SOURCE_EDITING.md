# 混合源码、团队编辑与文件操作

状态：产品要求已确认；协调协议、混合构建和长期持久化细节待阶段 0 验证。
本文定义跨模块合约；技术方案见 [ADR 0001](adr/0001-mixed-source-team-editing.md)。

## 1. 已确认要求

- LaTeX 与 Typst 均可打开、编辑、保存、另存为目标项目和用于最终输出。
- 团队协作时，同一共享文档同一时刻只能编辑一种源码语言；允许多人编辑该语言。
- 这是编辑限制，不是编译限制。两种引擎可按依赖关系顺序或并行构建。
- 不能原生转换的内容允许混用，范围包含正文、数学、图表、宏、模板及跨片段引用。
- 全范围是产品交付目标，不等于已验证任意程序或任意模板组合。每类能力必须有正向夹具和明确失败路径。

## 2. 四个独立概念

| 概念 | 含义 | 作用范围 |
|---|---|---|
| AuthorityMode | 正文以语义图还是源文件为准 | 项目，变更需迁移 |
| ActiveSourceDialect | 当前允许团队编辑的 LaTeX/Typst 语言 | 共享编辑范围，协调切换 |
| LayoutProfile | 宿主排版引擎、模板及混合策略 | 文档/构建 profile |
| ExportTarget | 本次源码项目、PDF、HTML 等交付目标 | 单次导出，不改变编辑语言 |

首发 SharedEditScope = ProjectId + BranchId，涵盖该分支全部入口、共享源码、宏和模板。这比逐窗口或逐文件锁
更严格，但能保证同一文档与其依赖不能被不同语言同时修改。未来缩小到无共享依赖的文档组需另立 ADR。
不同项目或独立分支可各自选择语言。同语言的多人编辑通过 CRDT 合并，不使用单人排他编辑锁。
Markdown/BibTeX 常规资源编辑不改变活动语言；若操作同时改写 LaTeX/Typst，按实际写集执行语言门禁。

## 3. 团队语言切换

协调者维护持久化控制记录 `scope, active_dialect, edit_epoch, phase, members`。
`edit_epoch` 是单调递增的隔离代数，不复用旧值，也不由 CRDT 的最后写入者决定语言。
单机未共享项目由本地 session 协调；共享分支由服务端原子控制记录协调，不依赖 presence 判断谁有写权限。

状态机：`Active(A, epoch) → Draining(A → B, epoch) → Active(B, epoch + 1)`。

1. 有编辑权限的成员提交带 expected_epoch 的切换请求；竞争请求最多一个成功，其他重新获取状态。
2. 协调者冻结新源码写许可。客户端结束当前 IME commit/动作，将待发送操作落盘，冲刷已获许可的旧语言写入，
   并确认各自的 accepted sequence。未完成或无法 reconcile 的源码单独保存为草稿。
3. 协调者等待在线写入者确认；掉线或超时者被隔离并收到待恢复提示，其未确认修改继续留在本地。
   UI 展示有草稿/被隔离的成员。强制结束等待需发起者显式选择，不能静默丢弃修改。
4. 完成旧语言写入屏障后，再为目标语言建立 generation/reconcile 基线；受影响的视觉修改若使基线过期则重算。
5. 原子提交新的语言和 epoch，广播新状态并发放目标语言写许可。另一语言的源码编辑器改为只读。
6. 已提交并有回执的重复包仍返回原回执；其他旧 epoch 包拒绝为 SourceEpochStale，不能进入共享内容。

取消/故障若回到原语言也发放新的 epoch，使切换前许可失效。服务重启从持久化状态恢复；不能因 presence
清空就重新开放两种语言。切换只影响写入；查看、编译和导出继续使用明确版本的快照。

控制状态需要确定顺序，正文继续使用 CRDT。源码写许可包含 scope、actor、dialect、epoch、许可 ID 和有效期；
写入提交由协调者检查当前状态，不能只检查本机缓存的 token。服务端持久化内容与许可校验在同一原子边界。

## 4. 门禁覆盖与离线行为

所有直接源码编辑、生成源码草稿、source lens、外部文件变更、格式化、重构，以及修改 ForeignSource 原文、
宏或模板的视觉命令，都声明实际 dialect 写集。跨两种语言的修改拆成两个可恢复步骤，经过团队切换；
不能用“语义操作”绕过源码门禁。纯语义正文编辑不受源码语言限制，派生生成文件不算另一语言的用户写入。
这里的纯语义编辑指 StructuredAuthority 的 SDG 操作；SourceAuthority 的视觉操作最终会改写权威源码，
因此按适配器实际生成的源码 patch 检查语言许可。
跨语言多步重构是可恢复工作流，不伪装成一次原子 WorkspaceTransaction；未完成时标记待完成并阻止受影响的
正式导出，可继续或生成补偿动作。每个同语言提交步骤自身仍是原子的。

门禁先于共享 CRDT 应用。服务端不能仅信任客户端声明的 dialect：协议按资源/绑定限定写入通道，对混合
语义更新做结构级写集校验，拒绝夹带未授权源码写入；无需执行宏或解析语言语义。该最小可信校验待 spike 验证，
未完成前不能宣称能阻止恶意客户端绕过。生成源码原文的团队可写草稿也在门禁内。

网络分区下无法同时保证共享分支的严格语言互斥和任意离线语言切换，因此：

- 独立本地项目可正常离线切换、编辑、保存和导出。
- 共享项目断线后，源码编辑保存为本地草稿或 fork；原有许可不能继续代表共享分支有权写入。
- 纯语义编辑可离线记录；涉及源码写集的操作转为草稿/fork。
- 重连后先同步控制状态，再让用户选择保留分支或请求目标语言并合入；所有修改经过当前基线校验。
- 不同语言的独立分支可分别工作；合并不能覆盖活动语言配置，必须按写集和当前 epoch 重新授权。

## 5. 混合内容模型

`Raw` 是不理解但保留的原文；`ForeignSource` 是具有语言、资源、作用域和执行合约的混合组件。
把 Raw 升级为可运行组件要解析依赖、选择受控工具链和建立桥接，不能仅改节点标签。

```text
ForeignSource {
  component_id, dialect, source_resource, entrypoint,
  placement: inline | block | section | document,
  effect: content | definitions | template,
  scope_id, dependencies, imported_symbols, exported_symbols,
  layout_contract, fallback, provenance
}
```

每个组件原文只有一个权威 ResourceId。语义图和转换 IR 只引用或携带不可变快照；编译产物是缓存。
源码项目可包含 `.tex` 和 `.typ`，但主入口、宿主 profile、组件引用与生成目录明确，不能靠扩展名猜权威关系。
生成视图不要求把两种语法直接拼成一个能被标准编译器解析的文件；使用具名绑定和独立组件源文件。

## 6. 混合范围与实现边界

| 内容 | 目标实现路径 | 必须验证的边界 |
|---|---|---|
| 行内数学、公式 | 原生转换或外语编译嵌入，保留基线/尺寸/原文 | 字体、基线、公式编号、选择与可访问文本 |
| 图片、表格、绘图 | 可理解表格转结构；复杂绘图用受控矢量资源或其他受支持载体 | 字体、裁剪、题注、标签、资源依赖 |
| 正文、跨页表格、章节 | 可理解内容原生转换；其余走结构/分页片段合约或独立章节装配 | 换页、脚注、目录、流式重排；不能只截图冒充可重排正文 |
| 自定义宏/函数 | 在所属引擎与声明 scope 内执行，通过类型化参数/结果桥接 | 定义顺序、闭包依赖、状态、同名符号与递归 |
| 模板与全局样式 | 一个最终宿主控制页面；另一语言模板限定组件/章节作用域，或显式映射到宿主 | 页眉页脚、计数器、字体、浮动体、全局副作用 |
| 跨组件引用 | 稳定符号 ID 与共享编号/引用表，必要时多轮构建 | 双向引用、目录/文献、最终页码、超链接目的地、循环与不收敛 |

两个引擎不会共享执行栈。LaTeX 宏不自动成为 Typst 函数，反向同理；跨引擎调用必须有声明的适配合约。
两个模板对同一页面的冲突要求用户选择宿主或分节策略。正文原文始终可编辑，但作为预渲染资源输出时，
不能承诺它在目标语言中仍是原生可编辑正文。

“都支持”的验收是各类内容均有经过验证的可用路径，不是只保存原文，也不是任意程序都可无损翻译。
不具备合约的组合标记 unresolved，保留全部原文并解释缺失能力；不能静默缩减需求或宣称目标已实现。

## 7. 混合构建

管线：`冻结输入快照 → 转换/依赖计划 → 外语组件构建 → 宿主排版 → 引用/布局桥接 → 最终验证`。

- 快照包含正文、所有组件、模板、资源、工具链及桥接版本；预览和导出都标识完整输入集。
- 无依赖组件可并行调用两个引擎。引用反馈形成有界多轮计划，不是无限递归执行循环依赖。
- 阶段 0 固定一个可配置默认轮数并验证；收敛指编号、页码、布局和链接清单达到规范化稳定状态。
- 页码读取最终宿主/装配结果；链接必须指向交付物中的有效目标，不能保留组件临时 PDF 的失效链接。
- 缺组件、转换失败、引用不收敛、未知分页或模板冲突阻止正式输出。快速预览可保留带诊断的旧结果/占位。
- 嵌入载体根据锁定工具链能力选取并记录 ADR，不能假定所有后端均接受所有 PDF/SVG 特性。
- HTML/Markdown 输出也需说明结构、可访问性和资源退化，PDF 中可嵌入不等于其他目标同样保真。

## 8. 文件操作

| 操作 | 明确语义 |
|---|---|
| 打开 `.tex` / `.typ` | 无元数据也能按原格式编辑；不执行项目命令、不自动重写正文 |
| 打开混合目录/包 | 校验 manifest、组件绑定和路径，缺依赖给报告，仍可编辑保存 |
| 保存 | 原格式文本最小写回；原生项目保存语义正文与组件原文；解析失败不阻止草稿落盘 |
| 同格式另存为 | 创建新项目身份与资源路径映射，默认不复制协作身份/权限；历史携带是显式选项 |
| 跨格式另存为 | 创建目标入口、资源与转换报告；成功后切换至独立目标项目，原项目保留 |
| 导出源码项目 | 生成 LaTeX 或 Typst 入口及完整资源；不改变当前权威模型、活动语言或工作项目 |
| 导出 PDF | 选择 LaTeX/Typst 宿主，按混合计划生成并验证最终结果 |
| 导出两套结果 | 对同一快照分别导出，显示各自报告，不要求串行运行两个编译器 |

原生/混合归档包保存：语义正文或权威源文件、组件、模板/资源绑定、版本化 manifest、必要原文与草稿。
manifest 文件名/序列化格式由持久化 ADR 决定；不能先发明扩展名作为已发布格式。
本地私人草稿默认不进入共享/发布包；完整备份可显式包含。参与导出的草稿必须先解析纳入快照或由用户明确
选择已提交正文，禁止在界面显示新内容时悄悄导出旧版本。

两种源码目标均提供两种交付方式：

- 标准工具链包：目标源码引用预生成资源，普通目标工具链即可构建；保留外语原文便于回到 Scholium 编辑。
  对嵌入资源的再生成需要外语工具链，不能声称目标源码可原生编辑全部内容。
- 可重建混合包：包含两种原文、依赖清单和声明式构建计划，需要 Scholium 构建驱动及两种锁定工具链。

标准包也必须实测干净环境构建；需要额外装配才能成立的布局不得标为仅目标工具链可构建。
可重建混合包不能伪装成无需依赖的单个 `.tex` / `.typ` 文件。
正式导出先写临时目录，完整性验证成功后发布；失败保留原项目与之前的成功产物。

## 9. 报告与验收

每节点报告：保真度 Exact/Equivalent/Degraded/Dropped/RawPreserved；执行路径
Native/ForeignRendered/Bridged/Unresolved；编辑性 NativeEditable/SourceEditable/ArtifactOnly；
可移植性 TargetToolchain/MixedToolchains/Unresolved。另附源位置、丢失属性、依赖与修复建议。
报告范围覆盖模板、定义、附件和桥接，不能只遍历已成功投影的正文。

必须通过：

1. 两位成员同语言同时编辑；另一语言全项目只读，source lens、宏、外部修改都不能绕过。
2. 并发切换、IME、未提交草稿、掉线、旧 epoch、服务重启和恶意写集测试；无双语言共享写入窗口。
3. 离线叉出另一语言，重连保住修改且经显式授权合入；语言控制记录不随历史回放倒退。
4. 混合正文、跨页表格、宏、模板、双向引用和文献项目保存重开，原文与依赖绑定完整。
5. 同一快照分别导出 LaTeX/Typst 源码包和 PDF，验证最终编号、目录、页码及链接。
6. 复杂语法、冲突模板、缺依赖、引用不收敛有可定位失败；预览占位不能通过正式输出。
7. 干净环境验证标准包和混合包的依赖声明，原文保留与目标可编辑性如实报告。
