# 报告 0046：当前页面编辑器体验审计

- 结论：**Fail（页面编辑操作验收）**。
- 日期：2026-09-26。
- 基线：`b2b4376`；测试对象是根 workspace 的正式应用，不是历史 spike。
- 对应：[阶段 1 最小编辑闭环](../plan/ROADMAP.md)、[原生 UI 验证项](../plan/NATIVE_UI_VALIDATION.md)、
  [渲染与编辑改进计划](../plan/RENDER_EDIT_REWORK.md)。本报告不改变阶段出口判定。
- 本次只增加测试、脚本与证据，没有修改编辑器运行时行为。

## 结论

用户报告的“公式后按回车把 `$` 带出来”可复现，且会破坏保存的语义内容。
这不是仅有一帧显示错误：原先的 `Inline::Math` 被改成两个 `Inline::Text`，
之后编译和保存都忠实保留了已经损坏的结构。

此外，旧字形坐标与当前文档坐标混用可让输入落到错误段落；点击和键入同帧到达时，
会触发字符串越界 panic。临时文字回显直接绘制 markup，又是另一类 `$` 暴露来源。
因此，仅调整 Typst 编译速度或栅格质量不足以修复本轮问题。

## 复现与测试边界

```bash
python3 scripts/audit-editor.py --native
# 只跑输入/字形体验契约：
python3 scripts/audit-editor.py --quick
# 单项崩溃复现：
cargo test -p scholium-app b13_stale -- --include-ignored --test-threads=1
```

原生脚本在独立 Xvfb 中启动自己的进程，使用独立 SQLite 夹具文件，按进程 ID 定位窗口，
只终止自己启动的应用。不会使用共享桌面输入注入、个人会话数据库或真实文稿。

输入契约在 `session/usability_audit/`：真实 egui `RawInput` → 页面编辑器 →
`SessionBridge::apply_pending_edit` → `LocalSession`。排版用例通过真实 Typst worker
获得字形位置，不手填“看起来应该在这里”的公式坐标。无窗口渲染断言检查 egui 绘制指令，
不冒充 GPU 像素验收；窗口脚本另检查真实截图和 SQLite 中的语义快照。

这些是主动审计用例，统一标为 opt-in，包含未实现的体验契约；审计脚本通过
`--include-ignored` 全部执行，失败不当作 expected failure。普通测试套件依然只验证其原有范围。
用例使用通过与失败对照：普通分段/合并通过，公式/粗体内部换行失败；普通公式输入和编译通过，
公式边界删除失败；当前字形定位通过，编辑后的旧字形定位失败。

锁定依赖为 egui/eframe 0.36.2、Typst 0.15.1；Rust、时间戳及完整提交身份见
[机器记录](evidence/SPK-0046/summary.json)。环境为 Linux、Xvfb X11、debug 构建。

但当前 eframe 的键盘与 `RequestPaste` 入口都会先归一化换行。因此不把该 RawInput 情况
列作用户可见故障；测试改为框架实际交付的 LF，窗口脚本分别验证两条 CRLF 入口。
同样没有用已弃用的 `ImeEvent::Disabled` 模拟取消；使用当前框架的空 `Preedit`。

## 根因证据

1. [`page_editor/input.rs`](../../crates/scholium-app/src/page_editor/input.rs) 的 Enter 路径
   无条件插入 `\n`，没有公式/格式边界判断；删除路径同样只删字符串范围。
2. [`range_edit.rs`](../../crates/scholium-document/src/range_edit.rs) 先拼接替换字符串、
   再按换行拆段并分别解析；不配对的 `$` 因而变成 Text。解析器不是凭空生成 `$`。
3. [`page_editor.rs`](../../crates/scholium-app/src/page_editor.rs) 的 `page_cells` 用
   **当前快照**的块长度和 UTF-8 边界解释**旧 revision**的字形偏移，随后再重放全局 shift。
   缩短文本时旧端点会先被过滤；前块增长时后块已经换过基址又被重复平移。
4. 同文件的 `optimistic_line` 直接把规范 markup 传入 `layout_no_wrap`，
   没有结构投影；且需要旧行字形才能回显，无法覆盖尚无字形的空文档和新段落。
5. [`commands.rs`](../../crates/scholium-app/src/commands.rs) 明确消费 Ctrl+Z/Y，
   当前没有动作撤销实现。这会放大结构误操作的损害。

## 性能观测

`c01` 对 1、50、200 段文档分别采样 40 次输入帧、10 次热编译等待，
每 4 次输入再编译一次；修改首段，保留期间的旧几何。数据写入汇总的 `METRIC` 行。

| 段数 | 输入帧 p50 / p95 | 热编译等待 p50 / p95 |
|---:|---:|---:|
| 1 | 2.320 / 6.978 ms | 10.193 / 10.286 ms |
| 50 | 64.467 / 82.559 ms | 121.992 / 132.164 ms |
| 200 | 64.846 / 81.131 ms | 1329.489 / 1365.939 ms |

输入帧包括 egui 页面处理、绘制指令生成和会话接受，不包括 GPU 呈现；
编译等待包括 worker 排队和 5 ms 轮询粒度，不包括整页栅格、纹理上传、屏幕刷新，
不能把两者相加当作端到端输入可见时间，也不能把 debug 数据当作发布版门禁。

本轮输入帧中仍有按字形反复构造块 markup、计算基址的工作，缓存整篇 buffer 并未消除这条成本。
先保证语义位置正确，再缓存对应 revision 的块基址/输入映射，才能同时解决正确性与帧开销。

## 是否改用另一种编辑方法

**建议改变编辑层与 Typst 的关系，保留 Typst 作为排版后端。** 这是基于本轮代码和实测的建议，
不是已经完成的架构迁移，也不是对替代引擎的性能承诺。

- 编辑器持有结构光标：块 ID、行内节点/数学槽位、叶子字素位置，以及节点内外的方向。
  `$` 属于投影语法，不能成为用户回车和退格能拆掉的正文字符。
- 回车、删除、跨段选区先形成语义操作，再生成 Typst 投影。公式退出/换行、粗体跨段延续等行为
  必须明确定义；不能先损坏字符串再依赖解析器猜测修复。
- 输入与当前光标行的局部布局在原生页面内即时完成；Typst 后台提供高质量分页排版。
  活跃行的过渡布局必须理解正文和公式，不直接把源码字符串盖在页面上。保持一个编辑面和一个权威文档。
- 每份命中几何携带对应 revision 的映射，旧坐标只经该 revision 的变更链转换一次；
  返回可验证的结构位置，无法安全映射时不能猜到另一段后继续写入。
- 先补结构保护、错误重定位和最小动作撤销，再评估局部增量布局。仅换成矢量绘制或更快的编译器，
  不能修复本报告中的结构破坏和越界。

这与现有设计中的 TreeCursor/Selection 方向一致；真正落地涉及模块边界时应另写 ADR 和实现计划。
单独给 Enter 补 `$` 只能覆盖一个例子，无法处理跨公式选区、删除、粗体、异步定位与字素边界。
