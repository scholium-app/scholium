## 怎么读这一页

出口条件是阶段 0 的"能不能进阶段 1"的判据。本页逐条给出**判定 + 证据位置 + 缺口**，
判定只用三种取值：**满足**、**部分满足**、**不满足**。凡"不满足"都给出下一步动作。

一键复现：`bash spikes/verify-stage0.sh`（分段落也可单独跑，见脚本头部注释）。

## 逐条判定

### 1. 中文 IME、嵌套数学光标、结构选区和源码工作台在原生候选中通过共同验收；记录锁定版本及真实平台

**部分满足。** 证据：[报告 0004](0004-native-ui-egui.md)、[ADR 0006](../adr/0006-native-ui-framework.md)。

| 子项 | 判定 | 证据 |
|---|---|---|
| 中文 IME | **满足** | 用户实机：预编辑到达、提交计数增长、中文进正文；预编辑期间核心动作不增长 |
| 嵌套数学光标 | **满足** | 共享核心 `Layout::caret` + 可见光标 + 输入法锚点；8 个无窗口输入契约测试 |
| **结构选区/结构编辑** | **部分满足** | 候选有结构编辑命令（包裹/解除/循环变体 + 按钮）并有 headless 测试；选区支持拖拽、Shift 扩展、同叶删除；**跨节点选区删除未实现** |
| 源码工作台 | **部分满足** | 只读 `TextEdit` + 方言/行数；可写模式与 reconcile 未接进界面 |
| 锁定版本与平台 | **满足** | egui/eframe 0.36.2、winit 0.30.13、accesskit 0.24.1；Arch Linux / niri 26.04 / fcitx5 5.1.22 |

缺口动作：跨节点选区的删除需要结构级编辑（与 ADR 0008 的 `SplitText`/`ReplaceRangeWithRaw` 一并做），
在阶段 1 之前完成；复制/剪切与整节点选中的视觉反馈同样待补。

### 2. 构建与运行不依赖 npm/Node.js/WebView；C/C++/Zig 依赖有明确 ABI、生命周期和构建记录，且许可证落入允许清单，`cargo deny` 通过

**满足。** 证据：`spikes/verify-stage0.sh web` / `license`。

- 无 npm/Node/WebView：仓库内无 `package.json`/`package-lock.json`/`yarn.lock`/`pnpm-lock.yaml`/`node_modules`；
  依赖树无 `wry`/`tauri`/`electron`/`webview2`（`deny.toml` 的 `bans.deny` 已把 `slint`/`wry`/`tauri` 列为禁止）。
- C/C++/Zig 依赖：**唯一**需要编译本地代码的路径是 `typst-eval → stacker → psm → cc`；
  `psm` 产出一个小型汇编 shim（见其构建产物 `...x86_64.o`），用途是深递归时的栈切换，
  ABI 局限在该 crate 内；`psm`/`cc` 均为 MIT OR Apache-2.0。除此之外无自研 C/C++/Zig 源码。
- 许可门禁：新增 `deny.toml`（按 `AGENT.md` 政策配置），**12 个 workspace 全部通过**
  `cargo deny --offline check licenses / bans / sources`（一键脚本 `license` 段可复现）。
  门禁期间真实拦下三类问题，都按政策处理并留下 ADR：

  | 被拦下的 | 处理 |
  |---|---|
  | `Apache-2.0 WITH LLVM-exception`（`ar_archive_writer`/`rustix`/`linux-raw-sys`） | [ADR 0005](../adr/0005-llvm-exception-license.md)：权限严格宽于 Apache-2.0，加入允许清单 |
  | `BSL-1.0`（`xxhash-rust`，Loro/Yrs 依赖） | [ADR 0010](../adr/0010-bsl-license.md)：OSI 宽松许可，加入允许清单 |
  | `OFL-1.1` + `Ubuntu-font-1.0`（`epaint_default_fonts`，egui 内置字体） | [ADR 0011](../adr/0011-font-asset-licenses.md)：**字体资产**单独一类，仅限未修改字体并要求登记 |

  另外修正了两处**我自己的验证缺陷**：① 先前的门禁检查只覆盖部分 workspace，
  漏掉了三个 UI 候选（正是 egui 的字体许可就在那里被发现）；② `bans.wildcards = "deny"`
  误伤了路径依赖（`{ path = "../.." }` 本就没有版本号），已改为 `allow-wildcard-paths = true`。
- **未运行**：`cargo deny check advisories` 需要联网获取 RustSec 数据库，本环境无法运行——
  明确记为未验证，CI 必须跑（脚本会在输出里提示，不假装通过）。

注意：`cargo deny` 目前**无法在仓库根运行**（根 workspace `members = []`），必须逐 crate 跑；
CI 接入时按 workspace 列表执行。

### 3. Typst 快速预览单字符路径 p95 不阻塞 16ms 帧，旧 revision 不闪回

**不满足（字面要求）；意图可通过架构满足。** 证据：[报告 0005](0005-typst-mapping.md) 的 `-- latency`。

| 路径 | 中位 | p95 | 最大 |
|---|---|---|---|
| 单字符路径（随机位置，20 页文档） | 19.2 ms | **21.3 ms** | 21.3 ms |
| 最坏：改首段（源码整体平移） | 18.9 ms | **207.8 ms** | 207.8 ms |

- 编译是**逻辑侧**耗时；若在后台线程执行、帧内只入队与取用最新结果，则帧**不被阻塞**——
  但预览刷新本身是几十到几百毫秒，不是 16 ms。
- 旧 revision 不闪回：结果门只采纳比已落地更新的 revision；乱序 `[2,5,3,4,1]` 最终采纳 5、
  忽略 3 次、闪回 0，且**带负对照**（朴素"谁最后到用谁"被同一用例抓出闪回）。

缺口动作：把条件改写成"编译异步、帧不阻塞、过期结果必须丢弃（含负对照测试）"，
并给出预览刷新的时延目标（建议 p95 ≤ 250 ms、可见页优先）。**这是条件表述问题，不是实现缺陷**，
但必须走文档修订而不是默认通过。

### 4. 受支持 LaTeX/Typst source edit 可 round-trip，Raw 不丢失

**满足（限定范围）。** 证据：[报告 0006](0006-source-reconcile.md)。

两种方言各 8 个用例全部通过：文本局部改字、结构内部叶子改字、整体换成受支持结构、
未知语法落成 `Raw`（原文逐字保留）、跨节点编辑 / 括号不闭合 / 增删行一律报冲突。
往返判据是"再生成的源码 == 人工编辑后的源码"。

限定：一次只处理一处编辑；不支持结构级重构（增删行、重排、文本中间新建结构）。
核心应补原子的 `SplitText` / `ReplaceRangeWithRaw`（见 ADR 0008）。

### 5. 两端收敛且本地撤销保留远端输入

**满足（自研实现 + 内存模型）。** 证据：[报告 0007](0007-crdt-race.md)、预筛 [0013](0013-crdt-prescreen.md)。

136 个用例逐条通过：收敛 14/14（两副本 × 两种合并顺序）、本地 undo 不回滚远端 5/5、
快照 5/5、10 万动作 2.94 s（堆增量 87.5 MiB）、随机化收敛 110 轮全部收敛。

限定：这是**自研最小实现**；第三方引擎（Loro/Yrs/Automerge）选型未做——
三者预筛均为 MIT 且无 C 依赖，对比夹具待跑（[ADR 0009](../adr/0009-crdt-engine.md) Proposed）。
树语义的边界（并发移动成环、`wrap`/`unwrap` 非原子）未解。

### 6. 不可信 LaTeX/Typst 无法执行外部命令或读取项目根外文件

**不满足。** 证据：[报告 0011](0011-untrusted-input.md)。

| 检查 | 结果 |
|---|---|
| `\write18`（shell escape 关闭） | **满足**：无副作用（且有开启时的对照夹具证明测试有效） |
| Typst `#read` / `#plugin` | **满足**：均被拒绝 |
| LaTeX 读项目外文件（`\openin` + `\read`） | **不满足**：默认配置下读到 `/etc/hostname` |
| 用 `openin_any=p` 限制 | **无效**：`kpsewhich` 显示取值已变，引擎仍读到文件 |
| OS 级沙箱（bwrap） | 能阻断读取（`/etc/hostname` 不可见、不再泄漏）；但**沙箱内良性编译未跑通** |

缺口动作：把条件改写成"编译进程在 OS 级沙箱内运行"，并在阶段 1 补齐沙箱配方
（只读挂载运行时与 TeX 资源、项目目录可写、无网络、独立命名空间），CI 用恶意夹具守。

### 7. 同一共享分支无两种源码语言同时可写窗口；离线及被隔离输入可恢复，旧 epoch 不自动回灌

**满足（内存模型 + 确定性时序；恢复侧另有实测）。** 证据：[报告 0009](0009-team-language.md)、[报告 0008](0008-build-recovery.md)。

60 个用例 60/60：切换屏障扫描出跨方言许可窗口重叠 **0**、无屏障语言变化 **0**；
epoch 1→2→3 且旧 epoch 包被拒、两种语言正文都没有它（不自动回灌）；重启后 9 条控制记录逐字段一致；
分区隔离写入被拒、重连旧草稿被拒、显式授权重放后标记恰好出现一次；19 类恶意写集逐条拒绝。

恢复侧（报告 0008）：WAL 在**正常关闭 / 尾部截断 / 尾部损坏**三种情况下都恢复到最后一个完整记录，
169 条随机截断断言全部落在真实记录边界；外部改动被检出并**拒绝静默覆盖**；
两引擎构建分目录隔离，毒饵对照证明『A 不读 B 的中间文件』。

限定：真实网络、多进程未验证（分区是内存标记、WAL 是简化帧格式）；
写集校验是字符串抽检而非解析器，**不能据此宣称能阻止恶意客户端**；
SIGKILL 不等于断电，真实掉电语义未测。
