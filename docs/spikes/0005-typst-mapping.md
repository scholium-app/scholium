- 代码：[`spikes/typst-mapping/`](../../spikes/typst-mapping/)
- 依赖版本：`typst = 0.15.1`、`typst-layout = 0.15.1`、`typst-kit = 0.15.1`（features `embedded-fonts`、`scan-fonts`）

## 要回答的问题

1. 语义图（SDG）能否稳定生成可编译的 Typst 源码？
2. `NodeId` ↔ 预览位置能否**双向**映射？
3. 增量编译能否达到"改一处不必全量重编"？
4. 20 页规模下编译要多久——这决定预览的调度方式。

## 做法

`spikes/typst-mapping/` 三个模块，全部复用共享核心的 SDG（`spikes/native-ui/core`）：

- `generator.rs`：递归生成 Typst。同时产出两样映射数据：
  **每个节点的字节范围**（`spans`）与**每个块级节点的 Typst 标签**（`labels`）。
- `world.rs`：最小 `typst::World`。单文件、无文件系统、无网络、`today` 返回 `None`；
  字体来自 `typst-kit`（内置 + 系统）。源码放在 `Mutex<Source>` 里，
  因此可以**原地替换源码而不重建 World**——这是增量编译能否命中的关键。
- `main.rs`：构造 20 页规模的 SDG → 生成 → 编译 → 双向映射 → 增量对照。

定位链路（全部用公开 API，无私有接口）：

```text
NodeId → 锚点名 → Introspector::query_label → Content::location()
       → PagedIntrospector::position → PagedPosition { page, point }
```

### 锚点机制：三次尝试才走通

要点是"给节点在预览里留一个可查询的位置标记"，而 Typst 的标签在不同模式下行为不同：

| 尝试 | 结果 |
|---|---|
| 块级 `<label>` | **可用**，但只在标记模式；下到数学模式会被解析成比较运算（报错 `unknown variable: nd`） |
| 数学模式内 `#label("…")` | **不可用**：能编译，但产生 256 条警告，且是**孤儿标签**（没有附着元素，1025 个标签只解析出 257 个） |
| `#context [#metadata(here()) <anchor>]` | **可用**：任何模式都行；`here()` 在布局期给出页码与坐标，元数据零宽、不改变排版 |

最终方案：每个节点在内容**前后各插一个锚点**（`nd-<n>-b` / `nd-<n>-e`），
于是节点有了"预览区间"，既能正向定位也能反向命中。

**一个必须校验的坑**：终点锚点可能被折到下一行，此时起止**不在同一行**，区间是假的
（曾观察到"零宽区间"）。反查因此要求起止同行；跨行时退化为"以起点为点"。
校验前后：1025 个节点里只有 **513** 个真正有可用的同行区间，此前若不校验会把假区间当真。

## 结果（20 页规模，release）

| 指标 | 数值 |
|---|---|
| SDG 规模 | 257 段 / 2 819 节点 |
| 生成源码 | 0.33 ms，30 535 字节 |
| **首次编译（冷）** | **637 ms**，**20 页** |
| 锚点解析 | **2 050 / 2 050**（1 025 个节点有起点；513 个有可用的同行区间） |
| 行内结构坐标 | **Fraction 256/256、Script 256/256**（同行区间）；Math 256/256（起点） |
| 反查（坐标 → 节点） | **Fraction 40/40、Script 40/40、Math 40/40 命中** |
| 源码偏移 → 节点 | 命中（偏移 53 773 → 节点 1400，与期望一致） |
| 渲染比对 | 标准夹具首页渲染并叠加锚点：绿线/红线精确框住分数、上下标、矩阵、根式（见下节） |
| 内容未变再编译 | 换新 World 17 ms；同 World 再编译 0 ms |
| **改动一处 + 持久 World** | **183 ms（冷编译的 29%）** |
| 改动一处 + 新建 World | 455 ms（冷编译的 71%） |

47 页规模（601 段 / 6 603 节点）的对照：冷编译 930 ms，位置映射 600 / 601，反查命中。

### 渲染比对：坐标确实落在元素上（不再是自洽）

往返测试只证明"用我自己的坐标能查回我自己"，那是**自洽**。为把自洽变成**证实**，
`cargo run --release --manifest-path spikes/typst-mapping/Cargo.toml -- render` 会：

1. 用标准夹具生成并编译；
2. 用 `typst-render` 把第 1 页渲染成位图（3 px/pt）；
3. 把每个锚点画上去——**起点绿色画在上半段、终点红色画在下半段**
   （相邻结构的起止常在同一 x，分开画才不互相遮挡）；
4. 输出整页图与数学结构区域的放大图。

证据：[artifacts/anchor-overlay-zoom.png](../../spikes/typst-mapping/artifacts/anchor-overlay-zoom.png)

读图：`|a/b|`、`|x₁²|`、`|(1 2; 3)|`、`|√y|`——每个结构的**绿线（起点）与红线（终点）
正好把它框住**；根式从 `√` 前一直框到 `y` 右侧。坐标确实落在正确的元素上。

另有两个自动检查：

- **顺序不变量**：同一行内各结构的 x 顺序必须与文档顺序一致，且同层区间不重叠 → **0 违例**；
- **墨迹存在性**：区间内不应完全没有内容 → **0 落空**。

一句诚实的记录：我最初设计的"区间内墨迹 vs 紧邻区间外墨迹"对比**没有区分度**
（正文密集时两侧都是约 0.16），已弃用，改为上面的顺序不变量加视觉核对。

## 结论

### 1. 生成与双向映射（含行内结构）：可用

`NodeId` 既能拿到源码字节范围（供源码透镜与诊断映射），也能拿到页码与坐标（供预览定位），
反查同样成立。**2 050 个锚点全部解析**，且行内结构（分数、上下标）**各自**有区间——
"点中预览里的一个上标 → 定位到该节点"这条路径已经验证。

两个"看起来能用、个别节点静默失效"的坑，都靠逐节点断言才发现：

1. **空段落**没有可附着的元素，标签解析不出位置；补零宽锚点（`#box(width: 0pt)`）解决。
2. **跨行的终点锚点**会给出假区间（曾出现零宽区间）；加入"起止必须同行"的校验后，
   1025 个节点里只有 513 个真正可用区间——不校验就会把假区间当成真区间。

### 2. 增量编译：有效但远不够交互

- **comemo 的缓存是按内容命中的，不只是按 World 身份**：内容未变时，换一个新建的 World
  编译只要 17 ms，同一个 World 再编译是 0 ms。
- 真正决定预览体验的是**改一处之后**：持久 World **183 ms**，新建 World 455 ms，冷编译 637 ms。
  持久的 World 值 2.5 倍。

### 3. 这条数字决定预览的设计（本节是给设计的输入，不是本项的失败）

**20 页文档每次改动重编译约 180 ms。**因此预览**不可能**做成"每次按键同步重编译"：

- 预览必须是**异步 + 去抖**的：显示"最后一次成功编译"的结果，标注版本，过期结果不覆盖新结果；
- p95 目标要按**百毫秒级**定，而不是按 16 ms 帧预算定；
- 若要更低的预览时延，只有两条路：把可见页/视口范围做局部编译，或做源码级差分
  （当前生成器每次重写整份源码，所有偏移都变，浪费了 typst 的解析缓存）。

## 已知简化与缺口（都是刻意的，正式实现必须补齐）

- **转义**：只处理了 Typst 标记中最常见的一小撮特殊字符，未覆盖数学模式与字符串语义。
- **行内结构坐标已补齐**：分数与上下标都有同行区间，反查 40/40 命中；
  公式与段落只有起点（终点锚点必然落在段末或换行处），反查用起点兜底，同样 40/40。
- **只验证了第 1 页**：渲染比对目前只覆盖首页与标准夹具，尚未在多页、跨页与换行场景下核对。
- **文本叶子仍无坐标**：只有块级节点、公式与行内结构有锚点；纯文本的字符级位置还没有，
  因此"点中正文里的某个字 → 定位到该文本节点"尚未验证。
- **矩阵**固定 2 列，未读取文档里的行列声明；分隔符、换行、分页都由 Typst 默认决定。
- **字体**取自系统（`typst-kit` 扫描），未做受控字体集合。正式实现必须解决字体来源与许可证，
  否则同一个文档在不同机器上分页不同，位置映射也就不稳定。
- **未做**：源码 diff 驱动的增量、局部编译、预览渲染（PNG/SVG）与点击命中的几何判定。

## 复现

```bash
export CARGO_HOME="$PWD/spikes/native-ui/.cargo-home"
cargo run --release --manifest-path spikes/typst-mapping/Cargo.toml
```

输出包含：SDG 规模、生成耗时与映射数、首次编译耗时与页数、位置映射解析率、
正反查结果、缓存探针与增量的三组对照。

```bash
# 锚点写法的探针（标记模式 / 数学模式）
cargo run --release --manifest-path spikes/typst-mapping/Cargo.toml -- probe

# 渲染比对：渲染首页并把锚点画上去，另做顺序不变量与墨迹存在性检查
cargo run --release --manifest-path spikes/typst-mapping/Cargo.toml -- render
```
