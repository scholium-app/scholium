# ADR 0048：共享数学输入引擎与数据驱动的键位表

- 状态：Accepted（方向，2026-11-02 由用户确认）；实现与验证见[数学输入计划](../plan/MATH_INPUT.md)
- 日期：2026-11-02
- 影响模块：app（命令注册表、键位）、session、typst、latex，新增数学输入模块
- 相关：[ADR 0041](ADR-0041-separate-latex-typst-kernels.md)、[ADR 0042](ADR-0042-session-editing-core.md)、
  [ADR 0045](ADR-0045-math-edge-caret.md)、[ADR 0046](ADR-0046-math-root-delimiter.md)、[ADR 0047](ADR-0047-display-formula-block.md)

## 背景

产品要达到 [Liii STEM](https://liiistem.cn/docs/guide-equation) 的数学编辑能力：组合符号（`<=` 得 ⩽、`RR` 得 ℝ）、
Tab 在形似/音似符号间循环、结构快捷键、结构变体循环、拆除最内层结构、矩阵行列增删、多行对齐、编号与引用。
调研见 [Liii STEM 体验调研](../research/LIIISTEM_EXPERIENCE.md)。

现状有四个问题：

1. 数学输入规则散在 Typst 会话代码里（`attach_key`、`$`、分数命令），LaTeX 内核无从复用。
2. 快捷键写死在 Rust 的 `CommandSpec`（`shortcuts: keys![KeyChord::ctrl(...)]`）里，`KeyChord` 只有 Ctrl 与 Shift，
   不能表达 Liii 大量使用的 Alt 组合，也无法让用户改键。
3. Tab 目前只做槽位跳转；Liii 让 Tab 做符号循环。[产品定义](../PRODUCT.md#3-默认编辑体验)已规定 Tab 承担命令补全、空槽导航与符号循环三种作用，
   由上下文决定并在界面明示，实现还没有这套规则。
4. 已实现的快捷键（Ctrl+M、Ctrl+/、Ctrl+Shift+R、Ctrl+Shift+E）未经统一设计，产品也从未发布。

## 决定

### 1. 数学输入引擎是共享底座

新增与 UI、Typst、LaTeX 都无关的数学输入模块。它接收抽象的键入与文字事件和当前数学上下文（所在槽位、光标前的原子），
输出抽象的数学编辑：插入符号、把光标前若干原子替换为组合符号、循环最后一个原子的变体、按模板插入结构并给出目标槽、
切换结构变体、拆除结构、增删矩阵行列或根指数。

规则全部来自声明式数据表，并由测试校验：

- **符号表**：以 Unicode 字符为键，带数学类别、LaTeX 命令名、Typst 名；某语言不能表达时显式标记。
- **组合规则**：字符序列到符号（含否定后缀 `/`、方向 `<` `>`、圆圈 `@` 等可发现的构词规律），前缀冲突由测试拒绝。
- **Tab 循环表**、**结构模板与变体表**、**`\` 命令名**（LaTeX 名为主，Typst 名为别名）。

`\` 命令输入属于同一引擎：在页面编辑中（正文与公式里都可以）键入 `\` 打开行内命令框，边输入边补全，
候选来自命令名表（符号、结构与正文命令），回车或 Tab 接受后插入对应符号或结构并把光标放进第一个必填槽，Esc 取消并保留原文。

数据表由本项目依据 Unicode 数据与公开文档独立编写，**不从 Mogan/TeXmacs 的键盘与循环定义文件提取**（GPL，AGENT.md 第 1 条）。

两个内核各写一个适配器：Typst 内核把数学编辑映射为结构文档上的 `StructuralEdit`；LaTeX 内核在页面内编辑公式时（L3），
把它映射为已确认数学范围内的最小 `.tex` 补丁（依赖 rtex 的公式源码归属）。同一按键序列在两种项目里得到等价公式，
由共享的验收脚本检查。

### 2. 键位表是数据，不在代码里

- 一张默认键位表随应用发布，按稳定的命令 id 绑定；Rust 代码里不再出现快捷键字面量。
- 组合键支持 Ctrl、Alt、Shift、Meta，macOS 上按平台惯例映射（Cmd 对应其他平台的 Ctrl，Option 对应 Alt）。
- 绑定有作用域：全局、页面正文、公式、源码编辑器、焦点结构类型；同一作用域内的冲突由测试拒绝。
- 用户键位文件叠加在默认表之上；帮助里的快捷键列表、菜单与工具提示都从生效的键位表生成。
- 只保留一版：新键位上线时旧键直接替换，不留别名。
- 字符序列规则（组合符号、Tab 循环、`$`、`^`、`_`、括号自动配对）不是快捷键，属于数学输入数据表。

### 3. 键位语义以 Liii/Mogan 习惯为基线

**Tab 不是万能键**，按上下文承担三种作用，Shift+Tab 反向，焦点工具栏始终提示此刻按 Tab 会发生什么：

1. 行内命令框打开时：补全当前候选；
2. 刚键入一个有候选组的字符、此后没有移动光标或执行其他操作时：在该组候选间循环，落定的符号才进入文档；
3. 其他情况：前进到下一个槽位，离开最后一个槽位时移到结构之后。

结构样式切换（分数形态、矩阵括号、行内↔独立公式等）走独立命令，不占用 Tab。
方向键在原子与槽位间移动，Alt+←/→ 按结构遍历；Alt+Shift+↑/↓ 循环结构变体；
Ctrl+Backspace 拆除最内层结构并保留内容；Alt+→/↓/Backspace/Delete 增删矩阵行列与根指数。`$` 插入行内公式，
独立公式、多行对齐与分数、根式、矩阵、上置/下置标注等结构键按 Liii 习惯取 Alt 系组合。键入 `(`、`[`、`{`、`|` 生成可伸缩的成对定界符。
具体默认绑定写在键位表里，不在本 ADR 固定；与窗口管理器或输入法冲突的组合可以在键位表里调整而不改代码。

### 4. 语义：只做影响排版结果的部分

写论文时需要、会改变排版输出的语义随结构一起实现：算子名（sin、log、lim、max 等直立并带算子间距，独立公式中上下限位置）、
直立常数与微分符号（e、i、d，供符合 GB 3102 的排版选择）、绝对值竖线与整除/集合构造竖线（`\mid`）的区分。

不改变排版结果的语义暂不实现：隐形乘号与分隔符、公式合法性着色、优先级高亮、复制到 Python/CAS。需要时另立 ADR。

## 后果

- 两种项目共用一套数学手感；新增符号或结构只改数据表与两个适配器。
- 已有的数学结构（分数、根式、定界符、上下标、独立公式）迁移到引擎之上，现有键位按第 3 条重定，
  [编辑体验](../EXPERIENCE.md)按本决定修订（快捷键改为引用键位表；Tab 三种作用；括号自动配对；`\` 行内命令）。
- 命令注册表的快捷键结构改为从键位表加载，需要处理 Alt 在 Linux 桌面上被窗口管理器占用的可能。
- 公式内中文输入法会截走组合符号所需的原始按键。是否在公式中默认关闭输入法组合（文本槽除外）**待验证**，
  在真实 fcitx5/niri 环境实测后在计划中裁决。

## 验证方法

见[数学输入计划](../plan/MATH_INPUT.md)的验收：数据表一致性测试、按键序列到结构的共享验收脚本（两个内核各跑一遍）、
键位冲突测试、真实窗口检查与输入法实测。
