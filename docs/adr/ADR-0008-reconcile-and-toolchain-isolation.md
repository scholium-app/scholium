# ADR 0008：源码 reconcile 策略与构建工具链隔离

- 状态：Accepted
- 日期：2026-09-16
- 决策者：ation_ciger
- 影响模块：源码工作台、reconcile、构建/导出、安全边界
- 关联：[ADR 0001 团队单一源码语言与混合项目](ADR-0001-mixed-source-team-editing.md)、报告 [0006](../spikes/0006-source-reconcile.md)、[0011](../spikes/0011-untrusted-input.md)

## 背景

两件事合成一个决策，因为它们都约束"外部源码 ↔ 语义图"这条边界：

1. **人工改源码后必须能映射回语义图**（受支持结构往返；未知语法变 `Raw` 且不丢内容）。
2. **不受信源码不得执行外部命令或读取项目根之外的文件**——这条是阶段 0 的出口条件。

## 验证方法

**reconcile（报告 0006）**：同一小文档生成 LaTeX 与 Typst，程序化模拟人工改写，8 条判据 × 2 种方言全部通过：
文本局部改字、结构内部叶子改字、整体换成受支持结构、未知语法落成 `Raw` 且原文逐字保留、
跨节点编辑 / 括号不闭合 / 增删行一律报冲突。往返判据为"再生成的源码 == 人工编辑后的源码"。

**隔离（报告 0011）**：实测 `xelatex` 与自写 Typst `World`：

| 攻击 | 结果 |
|---|---|
| `\write18{touch …}`（shell escape 关闭） | 无副作用 —— **有效** |
| 同上（显式 `-shell-escape`） | 副作用产生（基准夹具，证明上一行不是"命令没跑"） |
| `\openin` + `\read` 读 `/etc/hostname` | **读到了** —— 默认配置下即可读项目外文件 |
| 同上加 `-cnf-line=openin_any=p` | **仍然读到** —— 该设置约束不了引擎级 `\openin` |
| Typst `#read("/etc/hostname")` | 被拒绝（`file not found`） |
| Typst `#plugin("/bin/sh")` | 被拒绝 |
| `bwrap` 沙箱内跑同一份恶意文档 | `/etc/hostname` 不可见，**不再泄漏** |

## 候选方案

- **reconcile 全量解析**（真写 LaTeX/Typst 解析器）：能力最强，但工作量与"未知语法"边界都不可控，本阶段不选。
- **行 + 行内字节范围归因**（生成时记录行归属与节点范围，编辑后按最长公共前缀/后缀定位变更，
  归因给完全包含该区间的最内层节点）：实现可控、失败可检测。**采用**。
- **隔离靠 TeX 配置**（`openin_any=p`）：实测**无效**，不采用。
- **隔离靠"关闭 shell escape 就够了"**：只挡住命令执行，挡不住读文件。不采用。
- **OS 级沙箱**（bwrap：只读挂载运行时与 TeX 资源、项目目录可写、无网络、独立命名空间）：**采用**。

## 决策

1. **reconcile 采用"行 + 行内字节范围"归因**，归因结果只有四类：文本替换、结构包裹、落成 `Raw`、冲突。
   **归因不确定时一律报冲突**，不猜；不支持结构级重构（增删行、重排、在文本中间新建结构）。
2. **`Raw` 必须逐字保留**，且位置一致（把文本叶子拆成 `[前缀][Raw][后缀]`）。
   这条作为不变量，写入模块文档。
3. **共享核心需要原子的 `SplitText` 与 `ReplaceRangeWithRaw`**：本 spike 用
   `InsertNode` + `InsertText` + `DeleteRange` 手工拼出来，能工作但脆弱（顺序、下标、回滚都是手写）。
4. **LaTeX 编译必须在 OS 级沙箱内运行**，不依赖 TeX 配置；编译入口永远显式 `-no-shell-escape`，
   且不因"已经关了 shell escape"而省略沙箱。
5. **Typst 侧的 `World` 必须保持不变量**：除主文件与显式纳入的资源外，`file()` 一律返回 `NotFound`，
   且绝不访问磁盘。

**不承诺**：多编辑合并归因、结构级重构、真实网络/多进程沙箱、容器级隔离、解析器层攻击面（字体/图片解码）。

## 后果

正面：

- "未知语法不丢内容"由往返测试证实，而不是口头承诺。
- 安全结论来自实测：LaTeX 的读文件能力**不是配置问题而是隔离问题**，避免被"我们关了 shell escape"误导。
- Typst 侧按构造安全，攻击面收敛到"`World` 是否守不变量"这一个可测点上。

负面与风险：

- **出口条件需要改写**：当前表述"不可信 LaTeX/Typst 无法执行外部命令或读取项目根外文件"
  对 LaTeX 不成立（配置层面），必须写成"编译进程在 OS 级沙箱内运行"。
- 初轮 bwrap 配方未跑通良性编译；[报告 0016](../spikes/0016-working-tree-status.md) 已补齐，
  [报告 0017](../spikes/0017-mixed-build-isolation.md) 又将普通混合构建的 LaTeX 共用入口接入沙箱。
  运行时白名单、其他入口覆盖与资源边界仍待完成，不改变本 ADR 的隔离要求。
- 归因依赖行结构不变，重排或格式化会让所有行错位 → 全部落成冲突（安全但保守）。

需要新增的门禁：

- CI 用恶意夹具验证"沙箱必须阻断"（报告 0011 的检查可直接复用）。
- reconcile 的往返判据进回归：受支持编辑必须"再生成 == 编辑后源码"。

## 替换方案

reconcile 的归因层与解析层分离：将来引入真正的 LaTeX/Typst 解析器时，只需替换 `attribute` 一步，
四类归因结果与冲突策略不变。沙箱层与构建引擎无关：换成容器或 Landlock 只影响进程启动方式，
不影响构建调度与产物格式。
