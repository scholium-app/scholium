# ADR 0023：阶段 0 可行性边界与收尾

- 状态：Accepted
- 日期：2026-09-20；执行负责人：Codex
- 依据：用户明确要求“先核对，把必要的做了，spike 不需要打磨那么多细节”。
- 验证证据：[报告 0044](../spikes/SPK-0044-stage0-scope-review.md)。
- 调整范围：ADR 0015/0020/0022 的后续缺口不再自动成为阶段 0 阻塞；其技术限制仍有效。
  本 ADR 替代 ADR 索引把正式 parser、长期存储格式/schema 列为阶段 0 必须实现的阶段安排，
  不替代它们未来的技术选型，也不把实验 DTO 冻结为产品格式。

## 问题与候选

路线图定义阶段 0 为七项可行性 spike，阶段 1 才实现 collab engine adapter、storage WAL 和最小应用。
验收过程中把正式恢复、完整共享 SDG、任意数学读屏、跨平台和全资源配额逐步加入退出门槛，
造成已有原始判据证据仍不能收尾。ADR 索引也与 ADR 0008“本阶段不选全量解析器”冲突。

继续把生产缺口全部实现再退出，会使阶段 1 实质上在阶段 0 完成；直接删除限制并宣布产品完成则不真实。
采用固定可行性范围：保留明确夹具的正负验证、失败证据和选型；后续产品缺口登记到首次需要它的阶段。
以后只有已声明支持路径的崩溃、数据丢失、错误渲染/编辑、隔离失效或测试假通过才重开对应项。

## 决策

1. 原生共同验收限定锁定版本的 Linux 原生窗口与既有夹具。数学槽位、IME、结构选区、
   双源码、后台预览、十万行、系统辅助功能和实验会话恢复均需真实窗口证据。
   团队项允许原计划所述的受信模拟远端动作；独立 CRDT 收敛、语言门禁仍分别验收。
   不将单窗口注入宣称为共享 SDG CRDT，不在本阶段接生产网络和完整结构适配器。
2. 安全判据明确为：正常入口必须经 OS 沙箱；源码不能任意执行项目命令，不能读取项目输入、
   可写工作区与受信运行时白名单之外的宿主文件。字体、TeX 资源、动态库和固定工具是显式例外，
   不是项目可以申请任意挂载的授权接口。未声明的宿主文件与环境仍须负对照拒绝。
   这是对旧“根外任何文件不可读”的显式修订，不能称为证明了旧字面绝对要求。
3. 固定夹具研究 helper 不是项目打开入口；直接调用内部 worker 不提供安全承诺。
   要将这些入口用于外部项目时，先接入同一沙箱并复测。此约束不能用于豁免已有 UI、混合构建和包重建入口。
4. 已有墙钟、整树内存/任务数、临时空间、单文件和接收限制保留；/work 总配额仍未实现。
   不再为 P0 继续重写文件系统。面向不可信项目交付前，必须完成总输出配额和宿主解码/IPC 边界审查。
5. parser 本阶段以 ADR 0008 受支持子集/Raw/显式冲突为裁决；正式 CST/容错解析在阶段 1 源码功能前裁决。
   WAL 撕裂/草稿恢复机制与窗口快照可行性以报告 0008/0031 为证，不冻结永久 schema。
   SQLite/rusqlite → redb 验证与长期 schema/内容寻址 ADR 是阶段 1 正式存储开工前置，不能拖到交付后。
6. 阶段 1 的原生 shared SDG adapter 要验证真实树更新/身份、并发结构冲突和 actor undo。
   模拟结构窗口与源码 Loro 双副本仅提供各自证据，不能替代这项实现。

## 后果与替换

阶段 0 可以按明确子集结束；产品需求、双权威禁止、追加历史和混合构建六类覆盖不变。
任意源码支持、结构操作完整 undo/redo、人工读屏体验、Windows/macOS/WASM、持久身份/历史及
生产安全均不能从 P0 通过推断。后续若改平台、引擎、权威模型或支持范围，应新建对应验证，
无需重开未受影响的整套 spike，也不以“继续打磨”无限延长阶段 0。
