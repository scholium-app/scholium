# ADR 0017：PDF 产物探针使用独立运行时白名单

- 状态：Accepted（Linux 阶段 0 spike）
- 日期：2026-09-19
- 前序：[ADR 0012](ADR-0012-typst-worker-isolation.md)
- 证据：[报告 0033](../spikes/SPK-0033-build-entry-audit.md)

## 背景与候选

PDF 探针已进入 OS 沙箱，但复用包含 TeX、嵌套构建和基础文件工具的 full 清单。
继续共用扩大了不可信 PDF 解析时的可见资源；直接在宿主解析违反现有隔离方向。
选择复用同一监督/资源限制机制，为探针新增最小用途清单。

## 决策

受信调用方固定选择 `pdf-probe`，清空宿主环境，不从产物或项目选择清单。
只挂载 sh、prlimit、pdfinfo、pdftotext、pdftohtml、pdfimages 及其动态库，
字体、fontconfig 与 Poppler 资源只读目录。保留只读输入、独立输出、无网络命名空间和原有预算。
sh 仅执行固定 argv 重定向，文档内容不是 shell 程序。探针仍限制输入 64 MiB、返回读取 8 MiB，
单文件 64 MiB、地址空间 4 GiB、CPU 30 秒、墙钟 10 秒。

## 验证与后果

正对照 PDF 可由全部四个工具读取；畸形/符号链接/超大输入拒绝。
挂载探针验证字体与工具存在、输入不能修改、输出可写、宿主环境清空，TeX/curl/无关宿主目录不可见。
安全分段将 PDF 检查加入常规门禁。full 与 typst-editor 清单不改变。

不宣称沙箱中没有任何可执行程序：解析工具本身必须执行，完整构建也需要工具链。
此策略收紧可见集合，不解决原生解析器漏洞、进程总数、总输出量、其它 OS 或资源目录内部最小化。
不能将“项目根外运行时资源只读可见”写成“根外任何文件都不可读”。

## 替换

今后可改固定二进制 launcher、逐文件字体/资源清单或平台原生沙箱，须重跑同一正常/拒绝对照。
生产 BuildProfile 仍不接受任意 shell 或项目提供的可执行文件。
