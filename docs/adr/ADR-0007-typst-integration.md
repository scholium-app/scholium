# ADR 0007：Typst 生成、编译集成与位置映射

- 状态：Accepted
- 日期：2026-09-16
- 决策者：ation_ciger
- 影响模块：预览、渲染转换、源码映射、构建调度
- 关联：[ADR 0001 团队单一源码语言与混合项目](ADR-0001-mixed-source-team-editing.md)、报告 [0005](../spikes/0005-typst-mapping.md)

## 背景

产品要求"Typst 快速预览"并能**双向定位**：从语义节点找到预览里的位置，也能从预览里的点击找回节点。
同时源码工作台需要"节点 ↔ 源码范围"。这决定了生成器、编译器集成与 SourceMap 的形态。

## 验证方法

报告 0005 在 20 页规模（257 段 / 2 819 节点）上实测，全部可复现：

| 判据 | 结果 |
|---|---|
| 20 页生成 + 编译 | 首次编译 219 ms，20 页 |
| 源范围映射 | 逐节点字节范围；偏移反查命中 |
| 位置映射（正向） | 锚点 2 050 / 2 050 解析出页码与坐标 |
| 位置映射（反向） | 分数 / 上下标 / 公式各 40 个样本 **40 / 40 命中**，跨 19 页 |
| 坐标正确性（渲染比对） | 首页渲染后叠加锚点，绿/红标记精确框住分数、上下标、矩阵、根式 |
| 文本字符级 | 8 字一块插值误差平均 0.24 pt、最大 0.85 pt；反查完全一致 36/38 |
| 单字符路径时延 | 中位 19.2 ms，p95 21.3 ms；最坏（改首段）p95 **207.8 ms** |
| 旧 revision 不闪回 | 结果门验证（乱序到达忽略旧结果、负对照被抓出） |

## 候选方案

- **位置标记**：块级 `<label>`（只在标记模式可用）→ 数学模式内 `#label("…")`（孤儿标签，查询不到位置）
  → **`#context [#metadata(here()) <anchor>]`（任何模式可用，元数据零宽）**。采用第三种。
- **编译集成**：每次新建 `World`（内容未变可命中缓存，改动后无复用）→ **持久 `World` + 原地替换源码**
  （改动后重编译为冷编译的约 30%）。采用后者。
- **字符级映射**：每字符一个锚点（源码膨胀、编译变慢）→ **每 N 字符一块 + 按宽度比例插值**。采用后者。
- **同步 vs 异步编译**：同步编译会阻塞帧（p95 21 ms，最坏 208 ms）→ **异步 + 结果门**。采用后者。

## 决策

1. **生成器**：由 SDG 生成 Typst；同时产出每个节点的**源字节范围**与每个可定位元素的**锚点对**。
2. **位置映射**：锚点用 `#context [#metadata(here()) <name>]`；编译后用
   `Introspector::query_label` + `PagedIntrospector::position` 取 `{page, point}`。
   只有**起止在同一行**的锚点对才当作区间；跨行的退化为"以起点为点"。
3. **字符级定位**：文本叶子按字符切块（默认 8），块内按宽度比例插值；跨行的块不参与插值。
4. **编译集成**：**持久 `World`** + 原地替换源码；编译器版本锁定 `typst = 0.15.1`（含 layout/kit/render）。
5. **调度**：编译在后台进行，帧内只入队与取用最新结果；**只采纳比已落地更新的 revision**，
   旧结果一律丢弃（不闪回）。
6. **数学模式转义**：数学模式里凡不是单个 ASCII 字母/数字的文本一律加引号——
   `$ ax $` 会被当成变量名（实测报 `unknown variable`）。

**不承诺**：视口局部编译、源码级差分驱动增量、跨页结构的区间语义、预览的 GPU 光栅化路径。

## 后果

正面：

- 双向定位成立且有渲染级证据，不是自洽推断。
- 字符级精度足够（误差约为 0.06 个字），"点哪定位哪"可用。
- 锚点机制不依赖 Typst 私有接口，只用公开 API。

负面与风险：

- **预览不满足出口条件"16 ms 帧"的字面要求**（p95 21 ms，最坏 208 ms）。
  该条件应改写为"编译异步、帧不阻塞、结果门丢弃过期 revision"（见报告 0012）。
- 位置精度依赖**字体与排版稳定**：换机器/换字体会改变分页，映射随之变化。
  正式实现必须用受控字体集合，否则同一文档在不同机器上的页码不一致。
- 锚点让生成源码显著变大（20 页约 109 KB），并把编译从 219 ms 推高；需要评估更省的锚点密度。
- 升级 Typst 必须重跑锚点机制与 `position` API 的验证（0.15.1 已锁定）。

需要新增的门禁：

- 预览调度必须有"结果门"单测（报告 0005 的 `-- latency` 里已含负对照）。
- 字体来源必须受控并登记，否则定位与分页不可复现。

## 替换方案

生成器、SourceMap 与锚点协议都是本项目自己的接口；替换渲染后端（Typst 换版本、或换其它排版引擎）
只需重新实现"生成 + 定位"两层，SDG 与源码工作台不受影响。编译器依赖集中在
`spikes/typst-mapping/src/world.rs`（最小 `World`），替换面很小。
