# ADR 0030：公式输入期反馈与排版唤醒

- 状态：Accepted（本地交互预览）
- 日期：2026-09-24
- 影响模块：scholium-typst、scholium-app
- 接续：[ADR 0029](ADR-0029-direct-page-editing.md)

## 背景

用户在公式块中输入时遭遇“排版失败”和明显延迟。逐字输入 `alpha` 到 `al` 会触发
Typst `unknown variable: al`；`alpha/` 缺表达式，`sqrt(` 缺闭括号。
旧行为只保留旧页面，输入虽进入权威却不可见，不能完成直接编辑反馈。
首次系统字体扫描另约 2.4–2.6 秒，而短公式暖编译通常仅几毫秒。

## 候选方案

- 继续显示旧画面：保真但未完成输入不可见，拒绝。
- 弹出或覆盖一个普通输入框：违背页面直接编辑要求，拒绝。
- 在交互编译投影中仅把失败公式原位渲染为文字，保留映射与诊断：采用。
- 自动猜测公式含义、补全未知变量或修改权威：可能改变用户内容，拒绝。

## 决策

快照编译先执行严格 Typst。全部诊断可归属到具体 Math 源范围时，仅这些公式
在交互投影中显示为琥珀色源文字；其它内容仍由 Typst 正常排版。
重新编译使用同一语义 revision 的新映射，光标和选择继续直接作用在页上。
输入完成后下一次严格编译恢复数学形式。公式、保存内容、生成源码不变。

`CompileOutcome.warning` 表示输入期替代及原始诊断；`error` 表示仍无法生成页面。
所有未知来源、非公式错误维持失败行为；原始 `submit` 严格编译不降级。
正式输出不能使用交互替代页面作为有效产物。

应用提前启动字体扫描；请求通过通道唤醒常驻 worker，事件入队后通过回调唤醒 UI，
纹理采纳后请求下一帧。去抖和文档/revision/页码门控仍有效。
诊断面板展示真实原因；返回可视模式时恢复页面焦点。

## 验证方法

真实编译回归验证全部输入前缀、成功后清除提示、多公式隔离、原始源串不变、
严格编译仍失败以及事件唤醒。UI 回归先复现诊断不可见与切换丢焦点，再验证修复。
原生窗口按实际工具栏“独立公式”输入 `al → alpha → alpha/ → alpha/2`，
检查输入期字形、诊断和完成后的分式。代码、截图和耗时边界见
[复验证据](../spikes/evidence/SPK-0005/formula-input/README.md)。

## 后果与替换方案

未完成的子式会暂时显示源文字，可能发生局部重排；这不是完整数学槽位编辑器。
后续正式数学树应以空槽/局部结构排版替代整条公式的输入期文字，但保留
“权威不改写、反馈可编辑、诊断不隐瞒、最终输出严格”的约束。
提前扫描不能消除冷启动成本，不能把编译耗时当作键入到屏幕显示的全链路延迟。
