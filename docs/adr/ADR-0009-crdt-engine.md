# ADR 0009：CRDT 引擎选型

- 状态：**Accepted**（2026-09-16 由报告 0014 的夹具对比关闭：选定 Loro 1.16.0）
- 日期：2026-09-16
- 决策者：ation_ciger
- 影响模块：协同编辑、三层历史、持久化、同步协议
- 关联：[ADR 0001 团队单一源码语言与混合项目](ADR-0001-mixed-source-team-editing.md)、报告 [0007](../spikes/SPK-0007-crdt-race.md)、[0013](../spikes/SPK-0013-crdt-prescreen.md)

## 背景

[ADR 0001](ADR-0001-mixed-source-team-editing.md) 定了三层历史（CRDT / action / checkpoint）与
"共享树 + 共享文本"的协同编辑形态，并要求本地撤销保留远端输入。
报告 0007 用一个自写的最小 CRDT 验证了**收敛与撤销语义可达成**，但没有回答"用哪个引擎"。

## 验证方法

**已完成**：报告 0013 的预筛——三个候选的版本、许可证、依赖规模与本地代码依赖：

| 引擎 | 版本 | 许可 | C/FFI 依赖 |
|---|---|---|---|
| Loro | 1.16.0 | MIT | 无（只有非 Linux 目标的 `windows-sys`/`js-sys`） |
| Yrs | 0.27.4 | MIT | 无 |
| Automerge | 0.11.0 | MIT | 无 |

**待完成**（关闭本 ADR 的判据，全部要在同一份夹具上跑）：

1. 两副本离编辑后收敛（字节相等）与耗时；
2. **本地撤销保留远端输入**——三者 undo manager 的过滤语义不同，必须实测；
3. 快照往返，且快照后继续合并仍收敛；
4. 10 万次动作的耗时与内存；
5. `wasm32` 目标可编译（阶段 3 的 WASM 兼容要求）；
6. 树的可移动语义：用引擎自带 movable tree（Loro）还是"稳定节点 id + 父指针字段"自行建模——
   后者要在报告 0007 的最小实现上补齐移动的收敛证明。

## 候选方案

- **Loro 1.16**：唯一提供 **movable tree** 类型，直接对应"包裹/解除/重排"的语义；
  自带 `UndoManager` 与快照模式；较新，生态较小。
- **Yrs 0.27**：Yjs 的 Rust 移植，生态与实战检验最多；树是 XML 元素，**没有任意 move**；
  自带 undo manager 与 origin 过滤。
- **Automerge 0.11**：官方 Rust 实现，文档与历史模型最完整；**没有内置 undo manager**，
  也没有树类型，两样都要自己建模。

## 决策

**选定 Loro 1.16.0**（锁定 `=1.16.0`）。依据是报告 0014 的夹具对比：

- 两个决定性能力——**可移动树**与**能过滤远端输入的内置 undo**——只有 Loro 同时具备，
  且都在夹具上端到端跑通：`LoroTree` 的 `mov/mov_to/mov_after/mov_before` 直接对应包裹/解除/重排；
  `UndoManager` 实测撤销本地输入而保留远端输入。
- Yrs 的树是 XmlFragment/XmlElement，**全量检索无 mov 类 API**；Automerge **无 undo/redo API**。
  缺少的正是本项目最核心的两点，故不选。
- 顺带记录一个真实差异：同一位置的并发插入，Loro/Yrs 得 `你好world`、Automerge 得 `world你好`。
  三者都收敛，但收敛结果不同。

**明确不承诺**：本 ADR 未验证 Loro 的性能（吞吐、编码体积、内存、10 万动作规模）。
阶段 1 的第一个迭代必须补这项对比；若 Loro 明显劣于 Yrs，按"替换方案"转 Yrs 并自建移动语义。

### 2026-11-03 修订：阶段 1 性能停止条件触发

上述未测边界是阶段 0 的历史结论。T41 在同一份段落/行内文本/数学树夹具上完成两副本共十万动作的
Loro/Yrs 比较。五轮独立进程、交替顺序，release 构建；中文、emoji 与 `é` 文本，包含插字/删字、
节点创建/删除、包裹/解除与跨父节点移动。比较身份、属性、文字与有序子节点；十轮均收敛并通过快照往返。

| 指标（五轮中位数） | Loro 1.16.0 | Yrs 0.27.4 |
|---|---:|---:|
| 十万动作 ms（不含编码） | 254.30 | 191.86 |
| 两向纯引擎合并 ms | 4350.97 | 106.13 |
| 两向本地索引重建 ms | 33.23 | 10.18 |
| 两端全量 update 合计 bytes | 1894067 | 2881754 |
| 合并后 snapshot bytes | 1952007 | 2866614 |
| snapshot 导出 / 导入 ms | 78.75 / 35.54 | 10.54 / 106.69 |
| 两副本编辑后进程 RSS KiB | 108840 | 91676 |
| 整个进程峰值 RSS KiB | 259576 | 265568 |

Loro 的体积与快照导入较好，但该删除/移动密集负载的纯引擎合并约慢 41 倍，不能由索引重建解释。
因此 **T41 按任务规定停止生产 adapter/Action 格式实现并提交证据，不自行替换引擎**。
阶段 0 的功能选型保留；它不再足以授权生产 adapter 直接接入。
恢复实施前，协调者须裁决继续诊断/评估新版 Loro，或另行授权 Yrs 的移动/补偿语义证明与格式迁移。
没有接受 Yrs 为生产后端，也没有冻结 SDG Action payload；故本轮不立映射 ADR 0053。

版本核对：当前 crates.io 稳定版 Loro 1.17.1、Yrs 0.28.0。本轮保留原选型的 1.16.0/0.27.4，
避免把升级与映射变化混在一起；Loro 1.16.0 的宽松依赖会解析到不能编译的 loro-internal 1.17.1，
lockfile 将 internal 固定为 1.16.0，common/kv-store 为可编译的 1.17.0，完整解析以 Cargo.lock 为准。
当前锁定图的 Loro 探针通过 wasm32-unknown-unknown 编译；这不是尚未实现 adapter 的 WASM 验收。

Yrs 使用稳定 id + parent/order 字段及 tombstone，**不是已经证明并发任意移动正确的替代 adapter**；
本负载的两个 actor 编辑不同节点，不覆盖并发结构冲突、actor undo 或生产文档修复。
update 是从空 state vector 导出的全量历史，不是逐 Action envelope；Loro 保留操作历史，Yrs 使用默认 GC。
内存是 Linux 进程 RSS，峰值包含两副本、编码及恢复副本，不是纯引擎堆分配。
同机存在其它执行者，绝对时延不作产品预算；所有样本检查 monotonic/boottime，未发现挂起。
方法、复现与原始数据见 [T41 开发日志](../log/2026-11-03-loro-sdg-adapter.md)。

## 后果

- 阶段 1 可以把 Loro 写进正式依赖，但**接口仍按报告 0007 的操作语义定义**
  （操作集、因果序、undo 作用域），不把引擎类型暴露到三层历史之外，以保留可替换性。
- 必须有回归测试守住"撤销只作用于本地、远端输入保留"（报告 0014 的 Loro 用例可直接移植）。
- 报告 0007 的最小实现可作为"参照实现"：它是接口语义的定义来源，也是引擎对比的对照基线。
- 若最终选择引擎自带的可移动树，则"三层历史"的第二层（action）需要与引擎的 move 操作对齐，
  这会影响撤销语义，必须在 ADR 关闭时一并说明。

## 替换方案

接口按"操作集 + 因果序 + undo 作用域"定义，不暴露引擎类型；三层历史中的 CRDT 层是一个可替换后端。
替换代价集中在：编码格式迁移（需带兼容报告的迁移方案，见 `AGENT.md` 硬性约束第 3 条）与
move 语义的对齐验证。
