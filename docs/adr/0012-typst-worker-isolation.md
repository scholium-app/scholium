# ADR 0012：Typst 编译 worker 与显式运行时挂载

- 状态：Accepted
- 日期：2026-09-16
- 执行者：Codex（用户授权推进阶段 0）
- 影响模块：build、typst；当前实现仅限独立 mixed-build spike
- 关联：[ADR 0007](0007-typst-integration.md)、[ADR 0008](0008-reconcile-and-toolchain-isolation.md)、[报告 0018](../spikes/0018-typst-worker-isolation.md)

## 背景

限制 `World::file()` 能阻止未声明文件读取，却不能终止编译计算或限制内存。
原混合构建在主进程求值 Typst；LaTeX 已隔离，两个后端的资源边界不一致。
旧沙箱挂载整个 `/usr` 和库目录，也暴露了与工具链无关的文件。

## 验证方法

通过真正的 `--rebuild` 入口验证良性 PDF、未声明文件拒绝、无法有效记忆化的递归计算超时且不发布。
双宿主 36 次夹具、28 个包重建、既有安全判据和预览回归保持通过；原始数据见报告 0018。
运行时探针同时要求工具/字体/TeX 可用，以及无关目录和 curl 不可见。

## 候选方案

- 继续进程内编译：改动小，但不能安全终止任意求值；不采用。
- 全面改用 Typst CLI：适合预览，但现有编号/链接/位置内省需另外重建；本 spike 不选。
- 自有 worker 链接锁定 Typst crate：保留真实 Frame 和 Introspector 取证，可隔离求值及导出；采用。

## 决策

1. 普通混合构建的 Typst 宿主/组件通过固定 worker 执行编译、内省和 PDF/SVG 导出。
   主进程只接收数据结果，不接收或重建 `PagedDocument`。
2. worker 由当前受信 driver 启动，固定输入/输出路径、无任意命令或环境式绕过。
   每次使用新临时目录；失败/超时不在主进程重试编译。
3. 沿用统一 Linux 沙箱；10 秒 worker 墙钟预算，4 GiB 地址空间、30 秒 CPU、64 MiB 单文件上限。
   临时请求/结果带版本，读取上限 64 MiB；它们不是持久化或网络协议。
4. 运行时按固定工具清单及其动态库、locale、字体、TeX 和纸张配置挂载，不再映射整个 `/usr`。
   配方是受信代码，不从项目声明中获取可执行文件或挂载路径。

## 后果

计算超时可以结束子进程，主进程保留可读诊断；PDF/SVG 导出也受相同预算。
每次编译新进程会增加启动、字体扫描、序列化和二进制复制成本，跨请求不保留增量缓存。
ADR 0007 的持久 World 仍是将来受控长驻 worker 的性能方向；本轮不改变其映射结论。

当前白名单是 Arch Linux 配方，字体/TeX/locale 仍按资源目录挂载；未达到逐文件最小集合。
`ldd` 仅针对固定系统工具和调用方提供的受信工具链使用，绝不能用于项目中的任意二进制。
没有覆盖 seccomp、总磁盘/进程数量配额、恶意原生插件、解析器漏洞和其他平台。

## 替换方案

可改为受监督的长驻 worker，保留任务 revision、允许资源、超时与失败不发布语义；
平台替代沙箱必须重跑同一成功/失败夹具。临时 IPC 可更换为二进制数据和独立产物文件，
但不得把实验 JSON 格式变成产品存储承诺。
