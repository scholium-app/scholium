# ADR 0014：受监督的持久 Typst 编辑会话与局部纹理更新

- 状态：Accepted（阶段 0 spike 范围）
- 日期：2026-09-18
- 依据：用户反馈逐键冷编译和整页替换无法满足即时编辑
- 前序：[ADR 0013](ADR-0013-typst-editor-scene.md)
- 证据：[报告 0029](../spikes/SPK-0029-resident-typst-editor.md)

## 决策

编辑后台复用 OS 沙箱内的 Typst World、字体与 comemo 缓存，用 `Source::replace` 更新源码。
UI 不链接编译器，SDG 仍是唯一权威模型；不恢复旧自绘公式或把旧几何用于新内容。

每会话单个在途请求。后台写完私有输入快照后发送通知，在读取完整结果前不写下一份输入；
输入在沙箱内只读。结果包含完整页面/块清单与当前源码几何，UI 仍只采纳当前 revision。
跳过中间结果不会漏掉此前变更。会话失效会清空该会话的块缓存，失败不发布。

helper 以 128×128 像素块比较精确 RGBA，未改变的块复用资源，改变的块输出新资源并回收旧文件。
UI 持有页面纹理，用 `set_partial` 更新变化块；相同尺寸页面保留纹理身份，页面删除同步截断。
图像与几何仍在同一 UI 更新中采纳。状态栏单行截断，状态变化不再移动编辑区。

这是局部传输与纹理上传；当前 helper 仍逐页栅格化和比较像素，不宣称已实现局部排版树求值、
局部栅格化或仅重绘 GPU 的脏矩形。Typst 自身的求值/布局缓存可以跨请求复用。

## 生命周期与限制

- 每请求主进程等待最多 20 秒，超时/失败丢弃会话并终止监督进程；下一次编辑可以新建会话。
- 沙箱额外保持 300 秒总墙钟、30 秒累计 CPU、4 GiB 地址空间、64 MiB 单文件限制。
  会话年龄超过 240 秒时在下个请求前主动重建。累计 CPU 耗尽可能导致一次失败，随后编辑可重建；
  不将单次 CPU 配额伪装成持久会话的无限预算。
- Linux `PR_SET_PDEATHSIG` 绑定监督进程生命周期，`bwrap --die-with-parent` 终止命名空间内进程。
  正常 Drop 回收进程和临时目录；强制终止 UI 时进程可退出，但临时目录可能残留。
- comemo 定期淘汰缓存，旧块文件逐请求回收；UI 验证源码几何大小、页数、像素总数、完整块网格和块长度。
- 临时文件/通知是受信 spike 内部接口，不作为项目存储或网络协议。

## 取舍

没有选择在 UI 进程内运行编译器，也没有按段单独编译后拼接正文，避免失去隔离和完整分页语义。
首次启动、会话轮换仍有冷启动开销。大文档、复杂重排、连续输入的最终 GPU 呈现延迟仍需分别测量。
阶段 0 不因小夹具的改善而关闭。
