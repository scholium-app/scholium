# ADR 0001：团队单一源码语言与 LaTeX/Typst 混合项目

- 状态：Proposed
- 日期：2026-09-14
- 决策者：产品要求由用户确认；实现方案待技术验证
- 影响模块：model、document、format、latex、typst、build、render、storage、collab、history、app、sync-server

## 背景

用户明确要求源码编辑互斥覆盖团队，限制的是编辑语言而非编译器并发，并要求混用覆盖正文、公式、图表、
宏、模板和跨片段引用。旧设计仅限制单个源码工作台，Raw 保留也没有定义跨引擎执行与文件交付合约。

## 候选方案

1. 每个客户端自行选语言：不能满足团队约束，排除。
2. 两份整篇源码双向可写同步：产生双权威并无法一般性无损转换，排除。
3. 仅转换共同子集或只嵌入公式图片：不能覆盖用户要求的混用范围，不能作为完整交付。
4. 单一权威内容 + 分支级语言协调 + 有作用域的异语言组件：作为待验证方案。

## 决策

确认产品约束，提议方案 4。具体合约见 [混合源码与团队编辑](../MIXED_SOURCE_EDITING.md)。
源码编辑语言、正文权威、排版宿主和导出目标独立；同语言多人协作，异语言切换使用持久化 epoch 与写入屏障。
混用以 ForeignSource 和显式跨引擎桥接建模；保存保留原文，标准源码包与双工具链可重建包分别说明。

本 ADR 的 Proposed 指协调协议、桥接和存储实现尚未验证，不表示用户的产品要求可省略。
不在本 ADR 中锁定具体 CRDT、沙箱、嵌入载体、序列化或工具链版本。

## 验证方法

- 三客户端语言切换、掉线/重启、旧许可与恶意混合写集，要求共享分支无异语言同时可写窗口。
- 中英文跨页正文、表格、带宏绘图、两种模板作用域、双向引用、页码和超链接的真实混合夹具。
- 两种宿主分别导出标准源码包、混合重建包与 PDF；干净环境验证，确认不能支持的组合有明确错误。
- 草稿崩溃恢复、资源搬迁和导出失败注入；不丢原文，不覆盖成功产物。
- 记录混合构建收敛、时延、内存和安全隔离数据，确定可支持的模板/桥接矩阵。

当前尚无 spike 代码或实测数据；阶段 0 必须提交可复现命令与报告后，才能据证据接受或替换实现方案。

## 后果

共享分支断网时不能维持任意源码写入可用性：修改进入本地草稿/fork。服务端从纯中继增加控制记录与结构级
写集校验职责，但不执行排版或解释宏。混合正文与模板的排版/引用桥接显著增加工期，不沿用旧总周数承诺。

## 替换方案

协调存储和构建驱动可替换，但必须保留团队互斥、不丢草稿、原文单一权威与诚实导出的不变量。
细化到逐文档编辑范围或变更混合包持久化格式需新 ADR、迁移和恢复测试。
