# ADR 0043：LaTeX 实时预览采用沙箱内的 rtex 子进程

- 状态：Accepted
- 日期：2026-10-31
- 决策者：用户确认方向与 fork 策略；评估证据见下
- 影响模块：latex、build、render、app
- 前序：[ADR 0041](ADR-0041-separate-latex-typst-kernels.md)；计划见 [LaTeX 工作区计划](../plan/LATEX_WORKSPACE.md)

## 背景

ADR 0041 把 LaTeX 与 Typst 分成两个编辑内核，并规定 LaTeX 项目的预览必须由它自己的 LaTeX 引擎产生。
LuaLaTeX 项目的实时预览候选是 [realtime-tex（rtex）](https://github.com/HenryXiaoYang/realtime-tex)。它让一个已经加载导言区的
LuaLaTeX 只重排被编辑的单元，全局版面交给后台整编，输出与普通构建逐字形一致；MIT 许可，Rust 实现。

## 验证方法

按 LaTeX 工作区计划 L0 的 E1–E8 做了两轮评估，全部在 `rtex` 沙箱配置内运行，被测版本为 v0.0.5（`e0ad117`）：

- 第一轮（[日志](../log/2026-10-30-rtex-evaluation.md)）：E2 沙箱 Pass。负对照（读白名单外文件、`\input` 绝对路径、
  shell escape、写出构建目录、网络、死循环）在沙箱外均先证明攻击有效，在沙箱内均被挡住。E1 许可与来源通过，Linux 上不编译原生代码。
- 第二轮（[日志](../log/2026-10-30-rtex-evaluation-2.md)）：E3 中文 Pass（需持久化字体缓存），E4 绘制有条件通过，E5 定位 Pass，
  E6 宿主侧时延 Pass（100 页击键到单元栅格完成 p95 52 ms），E7 XeLaTeX/pdfLaTeX 整编预览 Pass，E8 故障**原样不通过**。

## 候选方案

1. **原样嵌入 rtex（库或子进程，不加防护）**：E8 不通过，而且 rtex 把 TeX 的写保护关掉了（`openout_any=a`）、信任宿主给的偏移与路径，排除。
2. **自研同类机制**：要重新实现 Lode 论文中的段落上下文捕获与逐字形验证，工期远大于给 rtex 加防护，排除。
3. **只用后台整编作预览**：可行但失去毫秒级实时性，作为 rtex 不可用时的退路保留。
4. **rtex 作为沙箱内子进程，放在 `latex` 模块的实时适配层后面，由宿主兜底已知缺陷**：采用。

## 决策

采用方案 4。条件：

1. **只在沙箱内运行。** `rtex serve` 和它启动的全部 LuaLaTeX 进程在 OS 沙箱内，项目只读、构建目录可写、无网络、看不到 `$HOME`。
   宿主只通过标准输入输出与它交换消息。不得在沙箱外处理任何文档。
2. **资源限制分两级。** 会话级用 cgroup 限制内存与进程数，常驻进程不设墙钟与 `RLIMIT_CPU`；单次编译由宿主计时，
   整编与导出另设一次性上限。现有 spike 沙箱的一次性限制不适用于常驻会话。
3. **字体缓存持久化。** 由可信步骤预热每用户字体缓存，每次会话挂载一份可写副本。不预热时首次布局约 13 s，
   luatexja 在 2 GiB 内存上限下会被杀掉。
4. **宿主兜底 rtex 的已知缺陷：**
   - 每轮后台编译设宿主看门狗，超时即终止并标为失败（rtex 会把被杀的编译报成 `Ok`，见上游 #22）；
   - 会话心跳与重启；收到 `EngineState Restarting/Failed` 后主动重新请求布局，补回在途编辑丢失的更新；
   - 转发前校验编辑：偏移落在 UTF-8 字符边界且不越界，路径是项目内的规范化相对路径。
5. **绘制。** display list 按不低于 2 倍像素密度栅格化，Type 1 字体经 `pdftex.map` 解析；display list 无法描述的页面
   （如 TikZ）用 hayro（MIT/Apache-2.0，纯 Rust）渲染 PDF 回退。
6. **数据通道。** 使用二进制 display list，不用 JSON 行承载版面（100 页一次布局约 14 MB）。
7. **定位。** 段落级定位用 rtex 原生的 span；字符级由宿主把字形对齐回源码。公式内部在使用 TFM 数学字体时只支持整体选中。
8. **适配层隔离。** 实时适配层对上只暴露段落更新、页面更新、定位与诊断事件，rtex 的类型与协议不进入公共接口。

### 上游与 fork

已向上游报告 #22（后台编译无超时）、#23（`openout_any=a`）、#24（lopdf 安全公告）。宿主无法兜住的是：后台编译超时与失败上报、
缺宏包时实时引擎反复重启、二进制 display list 通道。

- 截至 **2026-11-14** 上游对 #22–#24 无回应，就建立 fork。
- fork 的维护方式与 Typst fork（[ADR 0036](ADR-0036-typst-default-editor.md)）相同：锁定一个上游提交，按主题拆成独立小补丁
  并跟踪在仓库中，用脚本从上游原始对象加补丁重建，CI 校验结果一致；rtex 用独立的 Cargo workspace 构建，不进入主程序依赖图，
  `cargo deny` 单独运行。
- 每个补丁同时向上游提 PR；上游合并后删除对应补丁，使 fork 尽量薄。

## 修订（2026-11-01）

上游在一天内处理了我们报告的 #22–#27（[rtex#28](https://github.com/HenryXiaoYang/realtime-tex/pull/28)，随 **v0.0.6** 发布）：
后台、待机与导出编译有了 `pass_timeout`，超时或被信号杀掉的编译报告 `Failed`；越界、反向和落在字符中间的编辑范围返回错误；
`set_document` 拒绝项目外路径；缺宏包时实时引擎只失败一次、导言区改动前不再重启；lopdf 升级到 0.42。
`openout_any=a` 保留，上游的理由与本 ADR 一致：Lua 本身可写任意路径，安全边界只能是操作系统沙箱（已写入其嵌入文档）。

据此调整，原决策其余部分不变：

1. **锁定版本**：在 v0.0.6 上重跑第二轮 E8 故障注入，全部通过后把锁定版本从 v0.0.5 升到 v0.0.6。
2. **宿主兜底**：后台编译超时改用上游的 `pass_timeout`，宿主不再自建看门狗；会话心跳与重启、`EngineState Restarting/Failed`
   后补发布局保留（引擎崩溃时在途编辑仍无事件）；编辑偏移与路径校验保留在宿主，作为纵深防御。
3. **fork 条件**：“2026-11-14 无回应即 fork”不再适用，健壮性问题无需 fork。页面内公式编辑（LaTeX 工作区 L3）依赖的
   公式源码归属与空字段补丁（[评估记录](../log/2026-10-31-rtex-math-edit.md)）先以默认关闭的可选功能形式提议并提交给上游；
   L3 开工时若仍未进入上游，再按上文 Typst fork 的方式维护补丁。
4. **尚待上游的需求**：二进制 display list 通道、引擎崩溃时在途编辑的事件。在此之前宿主继续使用 JSON 行并自行补发。

## 后果

正面：LuaLaTeX 项目获得毫秒级、与最终构建逐字形一致的实时预览；中文 ctex 与 luatexja 文档可走实时路径。

负面与风险：
- 宿主要承担看门狗、校验、重启补发、字体缓存与栅格化等工作；
- 依赖一个发布不足一个月的上游，接口与格式仍会变；
- 可能需要维护第二个 fork；
- 只覆盖 LuaLaTeX，XeLaTeX/pdfLaTeX 项目只有整编预览（单次约 0.7–2.2 s）。

新增门禁：L1 在产品路径上复测 E2 的全部负对照，并在真实窗口内测 E6；宿主兜底的每一条都需要故障注入测试。

## 替换方案

适配层事件接口保持稳定。上游停滞或协议变化过大时，可换成 fork、自研实现，或退回只用整编预览，`latex` 模块之外不受影响。
