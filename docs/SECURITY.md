# 安全模型

## 1. 信任边界

不可信输入包括项目文件、LaTeX 宏、Typst 代码与构建配置、图片/字体、同步消息、导入压缩包、转换器输出和
共享成员身份。打开项目不等于授权执行其中命令。

ForeignSource 的 LaTeX/Typst 宏、模板、构建桥接和预生成资源都属于不可信输入。混合包声明不等于执行授权，
两个引擎分别适用相同沙箱；跨引擎参数传递是数据，不能拼接成 shell。限制组件数、依赖深度、构建轮数和总预算。
桥接生成的 PDF/SVG/HTML 与链接需检查，不能因来自另一受控组件就跳过产物验证。

## 2. 项目文件访问

- 所有项目相对路径规范化后必须仍位于项目根；symlink 按真实路径复验。
- `\input`、图片和 bibliography 的根外访问默认拒绝，用户可逐路径授权。
- 忽略设备文件、socket 和命名管道；单文件与总项目大小设上限。
- 导入压缩包防止 path traversal、符号链接逃逸和解压炸弹。

## 3. 构建隔离

- LaTeX 默认禁止 shell escape；Typst/转换器禁止任意进程调用；所有后端默认禁止网络和 post-build command。
- **关掉 shell escape 只挡得住命令执行，挡不住读文件——这是实测结论**（[报告 0011](spikes/0011-untrusted-input.md)）。
  在默认配置下，不可信 LaTeX 用 `\openin` + `\read` **真的读到了项目外文件**（`/etc/hostname`）；
  并且 TeX 自身的限制项**无效**：`-cnf-line=openin_any=p` 时 `kpsewhich` 显示取值已变，
  运行中的引擎仍然读到了文件（环境变量方式与 `pdflatex` 同样无效）。
  因此 **LaTeX 等外部引擎必须运行在 OS 级沙箱内**（只读挂载运行时与工具资源、项目输入只读、输出目录单独可写、
  无网络、独立 PID/挂载命名空间、以非特权用户运行），不能依赖 TeX 配置。
- **Typst 侧按构造安全，但依赖一个不变量**：`World::file()` 除主文件与显式纳入的资源外一律返回
  `NotFound`，且**绝不访问磁盘**。实测 `#read("/etc/hostname")` 与 `#plugin("/bin/sh")` 均被拒绝。
  这个不变量必须在实现与测试中守住——一旦为"方便"给 `World` 加上真实文件访问，攻击面立刻回来。
- 构建只读挂载/复制声明的输入，输出写入临时目录。
- 限制 CPU、内存、进程数、输出大小和墙上时间；取消必须终止完整进程树。
- 可执行工具链来自应用信任目录或用户明确选择，不执行项目内同名二进制。
- 构建产物经类型和大小验证后由原生渲染器展示；不内嵌浏览器，不执行 HTML/JavaScript。

需要高权限构建的项目使用单独 profile，并在每次首次启用时展示具体能力，不能只给“信任项目”
一个无限授权开关。

当前验证：Linux 配方的良性编译与隔离见[报告 0016](spikes/0016-working-tree-status.md)，
普通混合构建 LaTeX 入口的接入与覆盖矩阵见[报告 0017](spikes/0017-mixed-build-isolation.md)。
只读系统运行时是显式例外；目前 `/usr` 等挂载仍较宽，不能宣称项目根外所有文件不可读。
进程内 Typst、宿主侧产物探针与旧恢复实验的边界尚未全部统一。

## 4. 同步与身份

- 传输必须使用 TLS；token 存系统凭据库，不写进项目或日志。
- 服务端对每个 update 校验 project、branch、actor、权限 epoch、大小和速率。
- 邀请链接短期有效、单用途或可撤销，不携带永久 bearer token。
- owner/editor/viewer 在服务端执行；客户端判断只用于体验。
- presence 内容视为不可信文本，不进入 HTML 或日志模板未经转义。
- 团队源码活动语言由可靠控制记录维护，不依赖 presence。源码许可绑定 scope/actor/dialect/epoch/有效期，
  新写入必须校验当前控制状态，不能复用切换前或历史回放中的许可。
- 服务端检查实际源码写集，拒绝以普通 CRDT/语义更新夹带非活动语言的 ForeignSource、宏和模板改写。
  该结构级最小可信校验必须验证；不执行语言程序，也不能只信任客户端声明。旧协议不能绕过门禁。

## 5. 内容隐私

- telemetry 默认关闭或严格最小化，永不发送正文、文件名、citation key 或构建日志全文。
- 崩溃报告先本地脱敏并让用户预览。
- relay 存储策略、删除期限和备份策略必须公开。
- 端到端加密未落地前，不得宣称服务器无法读取内容。

## 6. 供应链

- 锁定依赖，CI 运行漏洞、许可证和来源检查；依赖许可必须落入 [AGENT.md](../AGENT.md) 许可证政策的
  允许清单，例外走 ADR。
- 外部贡献必须带 DCO 签署（`git commit -s`），保证来源与版权可追溯。
- 外部工具链记录版本与 hash；自动下载必须校验签名或固定 hash。
- 应用构建/运行不引入 npm、Node.js 或 JS UI 运行时；HTML 导出数据不作为应用代码执行。
- C/C++/Zig 依赖显式声明 ABI、内存所有权、线程约束和销毁顺序；异常/panic 不得跨 FFI 边界。登记处：[原生依赖登记](NATIVE_DEPENDENCIES.md)；新增此类依赖必须补录，`cargo deny` 只覆盖许可证、不覆盖这四项。
- 发布产物生成 SBOM，并进行平台签名和可复现性抽查。

## 7. 安全测试

对路径解析、压缩包、协议 decoder、LaTeX/BibTeX/Markdown parser 和构建日志 parser 做 fuzz。
集成测试覆盖 symlink 逃逸、shell escape、构建超时、超大输出、权限撤销、重放 update、乱序消息、
恶意 HTML 预览和敏感信息日志扫描。
新增混合组件资源逃逸、桥接代码注入、引用循环/预算耗尽、伪造 dialect/epoch、普通 update 夹带源码写入、
切换与权限撤销竞争、服务重启后旧许可复用、公开导出包泄漏私人草稿或写许可等用例。

## WASM 宿主边界

可选浏览器入口仅允许受信的工具生成 WASM 加载/绑定胶水，作为原生技术栈约束的有限补充；用户文档脚本仍是不可信内容，不能执行。Worker 不等于独立安全沙箱，资源、网络与计算预算由宿主执行。浏览器缺少 TeX 进程能力时不得静默上传构建；远程构建须由用户选择发送范围，服务端继续实施隔离。存储配额、驱逐和下载失败必须可见，详见[WASM 计划](WASM.md)。
