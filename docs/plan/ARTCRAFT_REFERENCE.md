# ArtCraft / PhotoCraft / WordCraft 借鉴计划

本计划记录从 ArtCraft 系列两款软件借鉴的架构与界面做法，以及在 Scholium 中的落地顺序：

- [PhotoCraft](https://github.com/storytold/photocraft)（考察提交 `583425b4df1c57a4515f591fed64fcedf8440cba`，2026-10-13）：
  纯 Rust、egui/eframe（wgpu）实现的分层图像编辑器。
- [WordCraft](https://github.com/storytold/wordcraft)（考察提交 `daf8caada33da7c033289e3a5e69a4a35948a862`，2026-10-15）：
  同系列、纯 Rust 的文字处理器，按 Microsoft Word 的功能面净室重写。与本项目同属文档编辑器，借鉴价值更高。

两者与本项目同为 MIT OR Apache-2.0 双许可。按[开发规范](../../AGENT.md)第 1 条，只借鉴设计结论与工程做法，
不搬运其源码；任何具体实现仍在本仓库独立完成并通过本仓库门禁。

本页是计划（将来时），不表示条目已实现。界面多语言单独见 [界面多语言计划](I18N.md)。

## 参考对象的核心做法

PhotoCraft 的架构以“界面只是引擎的一个客户端”为中心：

- **引擎优先、无界面优先。** 每个功能都能不经 GUI 调用：测试、CLI、JSON 控制通道和 MCP 共用同一引擎入口。
- **一切皆命令。** 约 700 个命令各有稳定 id（如 `filter.blur.gaussianBlur`）、标题、菜单路径、默认快捷键、
  参数 schema、`enabled`/`checked` 判定；菜单栏、命令面板、快捷键编辑器、动作录制、CLI 与 MCP 都从注册表生成。
- **数据描述界面，工具包只负责绘制。** 工具输出 overlay 图元数据，对话框由参数 schema 生成；
  面板读取由快照生成的 view-model。
- **前后端接缝很窄。** 前端只需要 `dispatch(command)`、只读快照、事件流、view-model 与工具接口；
  更换界面工具包不触碰核心。
- **分层由工具强制。** `cargo xtask layers` 在 CI 中检查 crate 依赖只能指向更低层，低层禁止依赖 UI 工具包。
- **设计令牌与共享控件。** 颜色、圆角全部来自语义令牌（chrome、field、hover、pressed、text/text_dim/text_faint、
  accent、separator 等），控件集中在共享模块，禁止在控件里硬编码颜色；界面字体打包 Inter 与 JetBrains Mono，
  另配 CJK 回退。视觉改动要在多种窗口尺寸、显示缩放和主题下截图核对。
- **两行界面骨架。** 顶部一行文字菜单（含文档名、命令搜索、工作区切换），第二行是随当前工具变化的
  上下文选项栏；其余空间留给画布，辅助面板停靠在侧边并可收起。
- **可编程驱动的运行实例。** 桌面程序可开启仅回环、令牌认证的 JSON 控制通道，代理可以检查界面、截图、
  派发命令，不依赖模拟键鼠。

## WordCraft：文档编辑器特有的做法

WordCraft 与 PhotoCraft 出自同一系列，架构骨架一致（命令注册表、分层门禁、与界面无关的会话、控制通道、
设计令牌），因此上述做法得到第二个项目的印证。以下是文档编辑器特有、对本项目更有价值的部分：

- **会话持有全部编辑交互状态。** `Session` 持有文档、选区、视觉列目标、输入样式、剪贴板片段、撤销与重做；
  一切操作都是 `Session::run(命令 id, 参数)`。界面只翻译事件、绘制结果，编辑行为可完全脱离 egui 测试。
- **命令失败原子。** `run` 执行前快照文档、选区、撤销/重做栈与输入分组；命令返回错误或发生 panic 时全部恢复，
  因此对外开放命令（控制通道、MCP）不会留下半改状态。
- **编辑行为以“规格表 + 测试名”固定。** 回车、退格、方向键、列表自动格式等按键行为写成表，每行指向
  钉住该行为的测试；行为经由与键盘相同的命令执行。
- **输入法预编辑不进入会话。** 会话只接收提交文字；预编辑由画布绘制，边界清楚。
- **结构化剪贴板片段。** 剪贴板保存文档片段，并附纯文本与 HTML 镜像，公式另附 MathML。
- **画布无障碍树。** 光栅画布为可见页面（含前后各一页）构建 AccessKit 树：段落、标题、表格、链接、
  每行文字及字符屏幕位置、文本选区，并限制节点总数。
- **无界面截图脚本。** 以 egui 测试框架离屏渲染，由逐行 JSON 脚本驱动操作并输出 PNG，作为主要视觉检查，
  不依赖真实显示与模拟键鼠。
- **敌意输入与不崩溃约束。** 对每个命令传入垃圾参数验证绝不 panic；核心 crate 根部禁止 `unwrap`/`expect`/`panic`；
  文件输入按“数字皆不可信”处理（检查算术、按索引取值用 `get`、限制分配）。
- **段落级排版缓存。** 段落带修订号作为缓存键，配合排版环境哈希；记录命中率并以性能测试固定逐键重排耗时。
- **分层检查拒绝未登记的 crate。** 新 crate 若未写入分层表，检查直接失败。

本项目在两点上优于 WordCraft，不应倒退：文档模型以稳定 `NodeId` 标识节点并有原生数学结构（WordCraft 以
段落扁平文本加字节偏移路径寻址，没有节点身份）；排版交给 Typst，而非自研排版引擎。

## 与本项目规范的对应

多数方向已经写在本项目规范里，只是尚未实现；PhotoCraft 提供了已跑通的组织方式与先后顺序。

| 做法 | 本项目现有规范 | 现状差距 |
|---|---|---|
| 命令注册表 | [应用模块 · 命令系统](../modules/app.md#命令系统)定义 `CommandSpec`；[编辑体验](../EXPERIENCE.md)要求菜单、快捷键、功能区调用同一命令，`\` 命令面板与声明式 command/cycle registry | 命令散落在 `ViewCommand`、功能区 `Command` 与硬编码快捷键表中，没有统一注册表 |
| 与 UI 无关的 session | [会话与扩展组织计划](EXTENSION_ORGANIZATION.md)：第二个调用入口出现时提取不依赖 UI 的 session | 光标、选区、撤销分组、输入样式、公式占位生命周期、视图跟随等编辑交互状态位于 `scholium-app` 的 egui 代码中，测试需模拟 egui 帧 |
| 控制通道 / MCP | [AI 与 MCP 扩展设计](AI_MCP.md) | 窗口验收依赖 xdotool 与 AUDIT 日志，焦点竞争和 X 错误是主要不稳定来源 |
| 设计令牌与控件 | [体验规范](../EXPERIENCE.md)、[P1 排版工作区规划](P1_UI.md)只约束布局关系 | `theme.rs` 只有少量颜色，部分控件自带颜色，没有共享控件模块和多尺寸视觉回归 |
| 菜单与工具栏 | [路线图](ROADMAP.md)阶段 1 写“标准菜单与紧凑工具栏”；P1_UI.md 与 EXPERIENCE.md 写 Ribbon 功能区 | 规范内部不一致；Ribbon 约占 170 逻辑像素且分组空旷 |
| 分层门禁 | 模块文档写明依赖方向 | 无自动检查 |

## 采纳项与顺序

1. **命令注册表（先做）。** 落地 `CommandSpec`：稳定 id、标题文本 key（见[界面多语言计划](I18N.md)）、
   菜单路径、默认快捷键、是否写入、`enabled`/`checked` 判定与参数 schema。菜单栏、格式栏、快捷键、
   状态与禁用原因都从注册表读取；新增命令放进按领域划分的新模块，不扩大共享文件。
   验收：去掉所有分散的命令枚举与快捷键表后，现有窗口检查全部通过；每个可见入口都能按 id 定位。
2. **界面骨架改为菜单栏 + 主工具栏 + 焦点工具栏 + 文档标签栏，并引入设计令牌。** 布局、设计稿、
   令牌表与组件规格已写入 [P1 排版工作区规划](P1_UI.md)，[体验规范的工作区组织](../EXPERIENCE.md#工作区组织)
   已同步改为该结构；实现时按令牌表实现语义颜色、字号、间距、圆角和栏高，控件集中到共享模块，
   并处理该页列出的设计稿问题，执行其中的已确认决策。
   验收：常规与窄窗口、1×/1.5×/2× 缩放、深浅两套主题下截图核对，无文字溢出、无硬编码颜色。
3. **提取不依赖 egui 的编辑交互核心（紧接采纳项 2，优先于新功能）。** 把光标、选区、视觉列目标、撤销分组、
   输入样式、占位生命周期、剪贴板与视图跟随意图移入不依赖 UI 工具包的 crate：输入为抽象的键、提交文字、
   指针（页面 pt 坐标）事件与命令调用，输出为编辑请求、光标与 overlay 数据；`scholium-app` 只负责事件翻译和绘制。
   输入法预编辑留在界面层，核心只接收提交文字。核心以 `run(命令 id, 参数)` 统一执行命令，并做到失败原子：
   执行前快照文档、选区、撤销/重做栈与输入分组，命令出错或 panic 时全部恢复。此项跨模块边界，先立 ADR，
   并与[会话与扩展组织计划](EXTENSION_ORGANIZATION.md)的 session 提取对齐，不另建平行结构。
   验收：同一编辑场景在无界面测试与真实窗口中产生相同的快照、光标与撤销结果；注入失败的命令不改变任何状态。
4. **编辑行为规格表。** 把回车、退格、删除、方向键、Home/End、Tab、Esc、公式进出、输入样式、撤销分组等行为
   写成表（按键 · 上下文 · 结果 · 测试名），每行由经核心命令执行的测试钉住；表放在
   [编辑体验](../EXPERIENCE.md)相关章节或其附表，行为变更必须同步改表与测试。
5. **分层门禁。** 增加一个解析 `cargo metadata` 的检查，禁止 app 以下的 crate 依赖 egui、eframe、winit，
   检查依赖方向，并让未登记进分层表的 crate 直接失败；接入 CI 的 lint 作业。
6. **不崩溃与敌意输入门禁。** 核心 crate 根部启用禁止 `unwrap`/`expect`/`panic` 的 lint（测试除外）；
   增加“每个命令都用垃圾参数调用一次且不得 panic”的测试；存储、Typst 结果与导入文件一律按不可信数据处理。
7. **无界面截图与控制通道。** 先以 egui 测试框架离屏渲染、逐行 JSON 脚本驱动的截图工具替代大部分基于
   xdotool 的窗口检查；再在 [AI 与 MCP 扩展设计](AI_MCP.md)的边界内，为运行中的程序提供仅回环、
   令牌认证（密钥文件权限 0600）的检查/截图/派发命令通道。权限、令牌存放与可写目录遵守 [安全设计](../SECURITY.md)。
   真实平台的输入法与读屏验收仍保留少量真实窗口检查。
8. **结构化剪贴板。** 复制得到文档片段（保留节点结构与数学节点），同时提供纯文本与 HTML 镜像，公式另附 MathML；
   粘贴优先使用片段，其次 HTML，最后纯文本，与[编辑体验](../EXPERIENCE.md)的多格式粘贴一致。
9. **排版增量与性能基线。** 测量 Typst 编辑内核能否按块缓存排版结果；能则引入块级缓存与命中率统计，
   不能则至少建立逐键排版耗时的性能测试与记录（多页文档），防止回退。
10. **画布无障碍树。** 在现有正文无障碍基础上，为可见页面构建段落、标题、公式、行与字符位置、选区的
    无障碍节点，限制节点总数；排在编辑交互核心之后，光标几何接口按此需求设计。

## 不采纳项

- 以某个商业软件为对标的逐项“对等度”评分体系：本项目按自身路线图与体验验收推进。
- 大量主题变体：保留浅色与深色两套即可。
- 超长单文件：继续执行 600 行文件规模门禁。
- 已在本项目确立的并行开发约定（固定工作树槽位、窗口检查机器锁）不再改为参考项目的每代理独立 target 目录。
- WordCraft 的 Ribbon 与 Word 对等范围（大量对话框、邮件合并、修订机制等）：本项目按 [P1 排版工作区规划](P1_UI.md)使用菜单栏与工具栏。
- 自研排版引擎：排版交给 Typst。
- 段落扁平文本 + 字节偏移路径的文档模型：保留本项目的节点身份与结构化数学。
- 以整文档克隆作为唯一撤销机制：本项目的协作与非线性历史需要动作层，不照搬。
- 以英文原文为 key 的 TSV 翻译目录：本项目已采用 Fluent（ADR 0040）；只借鉴其目录审计测试（占位符一致、目录无错误）。
- 只在本地运行的主门禁：本项目门禁保留在 CI。

## 完成标准

采纳项 1、2 完成后，界面所有命令入口来自注册表，顶部为菜单栏、主工具栏、焦点工具栏与标签栏四栏，令牌化主题通过多尺寸视觉核对；
采纳项 3、4 完成后，编辑交互的单元测试不再需要构造 egui 帧，按键行为有规格表与对应测试，失败命令不改变状态；
采纳项 5–7 以 CI 门禁与窗口检查的实际切换为准；采纳项 8–10 以各自验收测试为准。
