# 原生 UI 验证计划

> 本页是**验证方法与判据**（计划）；其中的状态叙述已移入 [log/stage0-progress.md](../log/stage0-progress.md)。
> 阶段 0 的**当前逐条判定以[报告 0012](../spikes/SPK-0012-exit-criteria.md) 为准**。

## 1. 固定顺序

1. **Iced**：首个验证候选，Rust UI 与 Rust 文档核心。
2. **GPUI**：第二候选，保持相同文档模型与验收脚本，更换 UI 适配层。
3. **C++ EUI-NEO**：第三候选，C++ UI 通过明确接口连接 Rust 核心。
4. **Slint 或 egui**：最后一组候选，进入此阶段时根据前三者的缺口决定先验证哪个，不默认两个都采用。

这是执行和比较顺序，不是最终选型，也不是同时引入多个 UI 框架。每个候选先产出 Pass/Fail/Blocked 报告，
再进入下一候选；首个候选通过不自动终止用户要求的后续比较。若要提前结束比较，记录用户的明确选择。
候选需要独立目录与锁定版本，不能将上一候选的 UI 状态或类型泄漏进核心。缺系统环境记 Blocked，不能记 Pass。

## 2. 技术栈边界

- UI、编辑模型、协作、存储与服务端优先 Rust；必要时混用 C/C++/Zig。
- Rust 构建使用 Cargo；原生依赖允许 CMake/原生编译工具。依赖图、版本与许可证可追溯。
- 不用 npm/Node.js、JavaScript/TypeScript 编辑器、WebView/Electron/Tauri 实现应用 UI 或候选验证。
- 不加载 GPUI 生态中可选的 JavaScript 扩展宿主。支持 JS 的第三方项目只评估其可独立构建的原生部分。
- Slint 候选允许编译期 UI 描述，但不得使用其 Node.js 绑定；这不放宽应用逻辑语言约束。
- HTML/MathML/Markdown 是导入导出数据，LaTeX/Typst 是文档语言；不因此引入浏览器 UI。
- OS 原生库与字体/图像依赖不要求全部用 Rust 重写。C/C++/Zig 跨界使用显式 ABI、长度、所有权和错误类型；
  不让异常/panic 跨边界，不传 Rust 内存布局、CRDT 内部对象或 UI 对象作为长期公共协议。

原有浏览器/ProseMirror 实验不构成原生路线验收证据，也不能扩充为正式实现。保留的旧实验原文不作为新计划依据。

## 3. 候选依据与待验证点

| 候选 | 已核对的上游资料 | 本项目必须验证 |
|---|---|---|
| Iced | [官方仓库](https://github.com/iced-rs/iced)、[输入法说明](https://book.iced.rs/faq.html) | 自定义数学结构、中文输入边界、可访问性、源码编辑状态适配 |
| GPUI | [官方 README](https://github.com/zed-industries/zed/blob/main/crates/gpui/README.md) | 版本变动成本、自定义布局、原生平台差异、输入法和无障碍 |
| EUI-NEO | [官方仓库](https://github.com/sudoevolve/EUI-NEO) | C++ UI/Rust FFI、文本塑形、IME 预编辑、数学控件、可访问树与平台覆盖 |
| Slint / egui | [Slint](https://slint.dev/)、[egui](https://github.com/emilk/egui) | 针对前三候选留下的缺口验证；不以普通 TextInput 替代完整编辑器；Slint 的许可证须先解决，见第 3.1 节 |

EUI-NEO 通常指 `sudoevolve/EUI-NEO`，上游声明 C++17、GLFW/SDL2 和 OpenGL/Vulkan；检索也会指向
`GTC2080/EUI-NEO`，仓库可能已迁移，验证前必须先确认当前上游。这些是上游能力描述，不是 Scholium 实测结论。
验证时固定具体 commit、窗口/渲染后端，检查其第三方字体和依赖许可证。
Iced/GPUI 等框架的文本输入和渲染基础不等于已具备科学文档结构编辑，不能沿用“成熟 Web 编辑器现成可用”的假设。

### 3.1 许可证前置

项目许可是 `MIT OR Apache-2.0` 双许可（[ADR 0004](../adr/ADR-0004-project-license.md)），候选的许可证直接决定它能否被采用：

- **Slint 不是宽松许可。** 上游提供 GPLv3、商业许可或 Slint Royalty-free 许可，三者都不是 MIT/Apache。
  在项目保持双许可的前提下链接 Slint，会把应用整体推向 GPLv3，或引入 royalty-free 许可的附加条款。
  因此 Slint 只能在其余候选全部失败、且用户明确选择改用相应 copyleft 或购买商业许可之后再验证；
  不能因为"它排最后"就默认可用。
- **EUI-NEO 许可证未核实。** 需先确认上游仓库、固定 commit 与许可证类别；未落入
  [AGENT.md](../../AGENT.md) 允许清单前不得进入验收。
- 每个候选的报告必须列出该框架及其必需传递依赖的许可证，以及它们对项目许可的影响；
  只写"依赖许可证可追溯"不算结论。

## 4. 每个候选使用同一最小工程

工程包含原生窗口、正文/源码/预览三个区域、可替换 UI 适配层与独立 Rust 文档核心。
使用相同语义样本、输入动作、字体、源码文件、编辑器协议与性能采样方式；测试数据可复用，UI 代码不混搭。
先验证单机核心路径，再接入模拟远端动作；网络服务实现不是选择 UI 的前置条件。

| 验收项 | 动作 | 通过条件 |
|---|---|---|
| 中文与 Unicode | 中文预编辑、选词、提交/取消；emoji/组合字符、粘贴 | preedit 不入历史，提交一次动作，光标/删除不拆坏字符；记录真实输入法 |
| 数学结构 | 分数嵌套根式、上下标、矩阵、文本与数学穿插 | 父子槽导航、结构选区、删除、撤销可用，非静态图像演示 |
| 源码视图 | 分别编辑 LaTeX/Typst，切换语言、保留语法错误草稿 | 文本修改可定位，未提交内容不丢；不采用 JS 编辑器 |
| 团队规则 | 同语言远端输入、视觉操作、旧 revision、语言切换 | 非活动语言只读，远端插入不被本地撤销删除，UI 不形成第二权威副本 |
| 核心集成 | UI 事件 → SemanticEdit/TextPatch → 核心确认 → 更新视图 | framework undo 不绕过项目历史，IME/选择状态与权威模型分离 |
| 预览 | 20 页 Typst 派生内容，点击定位、缩放、旧结果返回 | 映射到正确节点/版本，过期结果不改变当前光标；原生绘制 |
| 大源码 | 同一 10 万行夹具打开、滚动、局部编辑 | 记录耗时/峰值内存，按已有性能预算验收，不靠全量重排掩盖卡顿 |
| 可访问性 | 键盘遍历、焦点通知、角色/名称/文本与选区暴露 | 真实系统辅助功能检查，有缺口就记录失败，不能只检查按钮标签 |
| 文件恢复 | 打开、保存、重开、未完成草稿恢复 | 原文/草稿保留，IO 不阻塞输入 |
| 构建与依赖 | 清晰声明工具链，构建/启动测试工程 | 无 Node/npm/WebView 必需步骤，FFI 生命周期与错误边界可验证 |

先在当前可用 Linux 图形环境运行；Windows/macOS 分别记录结果。未测试平台标记未验证，不能由可编译推断
中文输入、无障碍和窗口行为通过。没有图形会话时可先跑模型测试，但 GUI/IME 项目保持 Blocked。

## 5. 记录与选型

每个候选报告必须包含：

- 框架 commit/version、Rust/原生编译器版本、OS、窗口后端、图形后端、字体、输入法与设备。
- 可复现的构建/运行/检查命令，各验收项 Pass/Fail/Blocked 和证据位置。
- 输入到确认 p95、预览延迟、大源码耗时、内存；与 `TESTING.md` 的预算对应。
- 需要自行开发或修复的编辑器能力、FFI 工作量、上游补丁、许可证和升级维护成本。
- 是否进入下一候选、原因以及不能拿静态演示替代的待解决项。

依次完成比较后再写最终选型 ADR。若均未通过，报告具体瓶颈，继续在用户允许的原生技术范围内调整；
不能自动退回 npm/WebView 路线。结构编辑、混合排版和团队协调的其他阶段 0 验证仍独立进行。

## WASM 补充维度

保留 Iced → GPUI → C++ EUI-NEO → Slint 或 egui 的原生验证顺序。每个报告增加 WASM 目标构建、浏览器输入法/渲染与所需宿主依赖列，不假定所有候选支持浏览器；原生和浏览器结果分别记录。优先共享 Rust 核心，可选浏览器仅允许工具生成的加载/绑定胶水，不用 npm/Node.js 或 JS/TS 编辑内核。详见[WASM 计划](WASM.md)与[全栈候选](TECH_STACK.md)。
