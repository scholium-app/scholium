# WASM 兼容计划

日期：2026-09-16。WASM 是优先兼容目标；当前尚无构建或运行验证结果，不承诺首发浏览器具备全部桌面功能。

## 范围与语言约束

先使语义模型、编辑动作、格式解析/投影、历史及协议编解码可编译到 `wasm32-unknown-unknown`，再验证浏览器应用。WASI 是另外的宿主目标，不等于浏览器 UI，也不自动提供桌面文件与子进程能力。

桌面继续使用原生 Rust 或 C/C++/Zig UI，不引入 WebView。浏览器可使用 Rust 编译的 WASM，以及必要的工具生成加载/绑定胶水；不引入 JS/TS 业务编辑器、npm 或 Node.js 工具链。`wasm-bindgen --target web` 提供无需 bundler 的加载路径，见[官方示例](https://wasm-bindgen.github.io/wasm-bindgen/examples/without-a-bundler.html)。这部分宿主胶水是对原生约束的有限补充，不能扩张为另一套 Web 编辑内核。

## 能力矩阵

以下均为计划边界，候选依赖必须以锁定版本的实际构建和运行结果确认。

| 能力 | 原生目标 | 浏览器目标与限制 |
|---|---|---|
| 文档/数学模型、动作、转换报告 | Rust 共享核心 | 优先同代码与同语料验证，不依赖本机句柄、文件或执行器 |
| 源码编辑与结构 UI | 按既定 GUI 顺序验证 | 单独测试输入法、剪贴板、焦点、无障碍与渲染；不能假定所有框架支持 |
| Typst 编译 | Rust 引擎集成或隔离 worker | 探索 Worker 内编译；字体/包/资源由宿主注入，验证启动体积、内存和取消 |
| LaTeX 编译 | TeX Live → Tectonic 验证 | 浏览器不能启动本机 TeX；本地 WASM 引擎为探索项，或用户显式选择远程构建 |
| 打开/保存 `.tex`、`.typ` 和混合包 | 本地文件适配、原子替换与恢复 | 文件选择/导入与下载导出作为基线；目录访问视浏览器能力增强，不能假设任意路径读写 |
| 历史与离线草稿 | SQLite/rusqlite → redb 验证 | IndexedDB / OPFS 宿主适配待比较，不默认复用本机数据库；测试配额、驱逐、异常关闭和导出备份 |
| 协作 | Rust CRDT + WebSocket | 共享 schema、锚点与协议；断线后源码写入仍遵守草稿与 epoch 合约 |
| PDF/SVG 预览 | 原生候选库 | 逐库验证 WASM 编译、字体/内存和宿主能力；C/C++ 原生二进制不能直接复用 |
| 进程与隔离 | OS 沙箱、无 shell argv | Worker 可终止计算但不是完整权限沙箱；资源访问由宿主控制，远端构建另有隔离 |

## 架构约束

- 核心不直接调用 `std::fs`、进程、平台线程、GUI 或具体数据库；宿主通过声明式输入、存储、调度和构建接口提供能力。
- 原生异步采用 Tokio；浏览器使用适配的 futures/Worker 调度，不无条件依赖 Tokio 多线程运行时、阻塞 IO 或进程 API。
- 浏览器先以单线程核心通过正确性验证；线程/共享内存优化另测跨源隔离要求，不能把相关部署头作为所有核心功能的前提。
- 持久性确认由宿主明确返回。IndexedDB/OPFS 的事务与刷盘语义不能直接等同本机 `fsync + rename`；UI 区分已编辑、已本地持久化、已同步与已导出。
- 统一文件包与协议版本、UTF-8/UTF-16 位置转换、稳定 ID 和错误模型；核心 API 不泄露原生指针或平台路径句柄。
- 无本地编译能力时显示能力缺失并保留源码。远程构建必须由用户选择并说明发送范围，不得为补齐浏览器能力静默上传文档、字体或附件。

## 验证顺序与出口

1. 阶段 0 建立最小纯 Rust 核心 fixture，原生及 WASM 目标编译，运行相同解析、编辑、序列化与转换报告测试；仅 cargo check 不算运行通过。
2. 用无 npm 的生成绑定与静态宿主完成浏览器 smoke：中文输入、导入两种源文件、保存重开、异常关闭恢复、协作重连。GUI 候选顺序不变，浏览器结果单列。
3. 分别验证 Typst Worker、PDF/SVG 和持久化适配；记录版本、浏览器/OS、命令、资源预算及 Pass/Fail/Blocked。没有结果不能把可编译写成可用。
4. 最后决定是否承诺完整浏览器发行；LaTeX 本地 WASM/远程构建和 WASI 另立 ADR。核心无法移植或候选依赖限制须在最终选型前披露。

详见[全栈候选](TECH_STACK.md)与[原生 UI 验证计划](NATIVE_UI_VALIDATION.md)。

插件组件属于独立扩展路线，见 [WIT 插件计划](WASM_PLUGINS.md)与 [组织计划](EXTENSION_ORGANIZATION.md)。共享核心编译到 WASM 不等于组件插件已能在浏览器运行。
