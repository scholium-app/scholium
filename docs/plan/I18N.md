# 界面多语言计划

本计划定义 Scholium 界面多语言（i18n）的范围、基础设施与分期。路线图把完整 i18n 放在
[阶段 6](ROADMAP.md#阶段-6扩展导出与产品化)；本计划把**基础设施前移**到命令注册表与界面改版时建立，
完整翻译仍在阶段 6 交付。理由与 [ArtCraft / PhotoCraft / WordCraft 借鉴计划](ARTCRAFT_REFERENCE.md)一致：
界面文字若先以硬编码中文散布全代码，之后再国际化就是全量替换；现在只需一次性建立目录和门禁。

本页是计划（将来时），不表示条目已实现。

## 三种“语言”不得混用

| 名称 | 含义 | 归属 |
|---|---|---|
| **界面语言** | 菜单、按钮、提示、状态栏、对话框、诊断与错误文字、读屏名称 | 本计划；用户偏好，可随时切换 |
| **文档语言** | 排版用的 `lang`/`region`（断行、引号、标点挤压、连字） | 文档样式（`scholium-typst` 的文档样式定义），属于文档内容，不随界面语言变化 |
| **源码语言** | 团队可写的 LaTeX / Typst | [混合源码与团队编辑](../MIXED_SOURCE_EDITING.md)，与本计划无关 |

切换界面语言不得改变文档、生成源码、修订号、撤销历史或保存内容。

## 范围

- 纳入：界面上所有用户可见文字，包括命令标题与提示、菜单、状态栏片段与瞬时警告、对话框、空状态、
  无障碍名称与播报（AT-SPI）、诊断与错误信息。
- 不纳入：文档正文与用户命名（文件名、标签）、生成的 Typst 源码、命令 id、AUDIT 字段与日志键、
  开发与测试输出。
- 首批语言：**简体中文（zh-Hans）** 与 **英语（en）**，两者都要求完整覆盖；其他语言在阶段 6 按需加入，
  缺项回退英语。从右到左书写（RTL）界面首批不支持，明确记录为限制。

## 基础设施

1. **稳定 key，不以显示文字为 key。** key 为 ASCII 语义名；命令文字从命令注册表 id 派生
   （如 `command.<id>.title`、`command.<id>.tooltip`），其余按区域命名（`status.*`、`dialog.*`、`a11y.*`、
   `diag.<code>`）。翻译文字修改不影响 key、测试和快捷键配置。
2. **底层 crate 不产出界面文字。** `scholium-model`、`scholium-document`、`scholium-storage`、`scholium-typst`
   的错误与诊断改为“稳定 code + 结构化参数”，沿用 [数据模型](../DATA_MODEL.md)中可本地化诊断（`LocalizedMessage`）
   的约定；由 app 按当前界面语言渲染。排版内容中的可见占位（如原串公式占位）属于预览输出，单独评估是否随界面语言。
3. **目录格式与库。** 候选为 Project Fluent（`fluent-bundle`，CLDR 复数规则、命名参数、选择器）与自研简单目录
   （TSV/TOML + 自定义复数表）。实现前以 ADR 裁决：许可须过 `cargo deny`，须能编译到 wasm（见
   [WASM 计划](WASM.md)），默认倾向使用成熟库。目录随程序编译嵌入，不在运行时下载。
4. **格式化规则。** 一律使用带命名参数的完整句子，禁止拼接句子片段；数字、计数与单位走目录的复数和格式规则；
   快捷键显示按平台惯例（Ctrl / ⌘），不翻译键名。
5. **运行时切换。** 偏好默认 `auto`（跟随系统界面语言，不支持时用英语）；手动选择后持久保存；
   切换后下一帧生效，无需重启，打开的文档与撤销历史保持不变。
6. **版式容错。** 英文通常比中文长：控件不按中文宽度写死；单行区域使用省略并悬停显示全文（沿用状态栏警告做法）；
   任何界面语言下都保留 CJK 字体回退，以正确显示中文文件名与文档标题。

## 门禁

- **禁止新增硬编码界面文字。** 检查脚本扫描 `scholium-app` 与底层 crate 的非测试代码，含 CJK 字符的字符串字面量
  只允许出现在目录文件或白名单（如排版内容常量）中；接入 CI 的 lint 作业。现状约有 330 处硬编码中文字面量
  （app 约 240 处，其余为底层 crate 的错误文字），迁移期用白名单逐步收敛，白名单只减不增。
- **覆盖与一致。** zh-Hans 与 en 必须覆盖全部 key；目录中不得有未使用的 key；每个注册命令都有标题 key。
- **测试不依赖显示文字。** 窗口检查与单元测试按命令 id、无障碍 id 或 key 定位控件，不按中文/英文标签定位，
  切换界面语言后同一套窗口检查必须全部通过。
- **多语言视觉核对。** 界面改版的多尺寸截图核对同时覆盖 zh-Hans 与 en，窄窗口下无文字溢出与重叠。

## 分期

1. **随命令注册表与界面改版建立（阶段 1–2 期间）。** 落地目录、key 规则、运行时切换与上述门禁；
   新菜单栏、格式栏、状态栏与所有命令文字一次性进入目录，zh-Hans 与 en 完整；
   底层 crate 错误改为 code + 参数；现有硬编码字面量进入白名单并逐步迁移。
2. **阶段 6 产品化。** 迁移剩余文字并清空白名单；按需增加语言与翻译贡献流程；
   与三平台打包一起验证系统语言探测和各平台读屏的语言表现。

## 完成标准

阶段 1–2 部分完成时：界面在 zh-Hans 与 en 之间运行时切换，菜单、格式栏、状态栏、命令提示与读屏名称全部随之变化，
文档与历史不变，全部窗口检查在两种界面语言下通过，硬编码检查进入 CI 且白名单不再增长。
阶段 6 完成时：白名单为空，诊断与错误全部经目录渲染。
