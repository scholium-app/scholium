# E1 实施计划：结构光标取代全局字节偏移

本页是[渲染与编辑改进计划](RENDER_EDIT_REWORK.md)中 **E1（坐标模型重建）** 的实施计划（将来时），
依据[报告 0046](../spikes/SPK-0046-editor-usability-audit.md)的 Fail 结论与根因证据。
它定义要做什么、什么算通过、怎么回退；**不声称任何条目已实现**。
当前阶段判定仍只见[报告 0012](../spikes/SPK-0012-exit-criteria.md)。

## 为什么是 E1 而不是打补丁

报告 0046 的 19 项失败里，8 项（a01–a06、b01、b10）是**同一类**问题：编辑层把
「全文档拼接 markup 的字节偏移」当作唯一坐标，于是 `$`、`*`、`_` 这些**投影语法**
成了用户可以回车和退格拆掉的正文字符。另外 3 项（b06–b08）是旧 revision 字形偏移
被**当前**快照解释。1 项（b13）是同帧点击与键入造成的越界 panic。

这些不是四个独立缺陷，而是同一个坐标模型缺陷的四个表现。给 Enter 加一条"别拆 `$`"
的判断只能盖住 a01/a02，盖不住 a03（公式内部回车）、a05/a06（边界删除）、
a04（粗体跨段延续）和 b01（真实字形命中后的同一条路径）。因此本计划重建坐标模型。

**与既有规范的关系**：编辑权威仍是语义文档图，页面编辑器仍是投影 + 工作缓冲
（[硬性约束 2](../../AGENT.md)）；不引入第二个可写权威。`docs/modules/document.md` 已把
TreeCursor 定义为"指向合法槽边界或文本相对位置，不指向渲染坐标"——E1 是把
`page_editor` 拉回这条既有规范，不是新立方向。框架仍为 egui（[ADR 0006](../adr/ADR-0006-native-ui-framework.md)）。

## 目标模型

三层坐标，各司其职，禁止混用：

| 层 | 类型 | 用途 | 不用于 |
|---|---|---|---|
| 语义位置 | `BlockPosition`（已有）/ 结构路径 | 编辑请求、选区、撤销记录 | 绘制 |
| 投影字节 | 拼接 markup 的 UTF-8 byte offset | 只在与 `BlockEdit` 互转时临时构造 | 长期持有的光标状态 |
| 页面几何 | revision 绑定的字形矩形 | 命中测试、绘制 | 编辑请求 |

**核心不变量（E1 的验收本质）**：

1. **光标不再是长期持有的全局字节偏移**。编辑器持有 `Caret`：块 ID + 块内结构地址
   （行内节点序号 + 叶内字素索引）+ 方向 + 可选选区锚点。
2. **`$` / `*` / `_` 是投影语法，不是正文字符**。回车、退格、Delete、粘贴先在结构层
   形成语义操作，再由投影生成 markup；不存在"先损坏字符串、再指望解析器猜回来"的路径。
3. **结构操作有明确定义**，且都保持内容不丢失：公式内回车、公式边界退格、粗体跨段延续、
   定界符相邻删除，每一项都要在计划里定义清楚期望语义并写成测试。
4. **几何按产生它的 revision 解释**。每份命中几何携带产生它的 revision，旧坐标只经
   从该 revision 起的变更链转换**一次**，映射不可靠时返回"无法定位"而不是猜一个段落继续写。
5. **撤销**：Ctrl+Z 不再被消费却无实现（[`commands.rs`](../../crates/scholium-app/src/commands.rs)）。

### S2：引入 `Caret` 与 `EditCommand`，替换 `EditorState` 的坐标字段

这是本计划**唯一的大改动**，其余步骤都在其上进行。

**范围修正（实施中发现）**：原计划把 `command.rs` 划给 S3、只让 S2 换坐标类型。这是错的。
审计基线 32 项中通过的那 13 项里，`a11`（分段合并）、`a12`/`a18`（跨块选区）、
`a07`（粘贴等于键入）、`b07`/`b08`/`b13`（几何命中落点）、`b09`（跨越公式边界）
**本身就是字节偏移模型的副产物**：它们的跨块行为由「拼接串切片 + 重新解析」实现。
一旦 `Caret` 成为权威，"跨块"在单个 `Caret` 里没有表示，这些用例必然掉队。
因此 **S2 必须同时引入 `EditCommand`**，否则会出现"结构权威但跨块功能消失"的中间态，
反而比基线更差。S2 与 S3 的边界因此调整为：S2 建立命令层与结构寻址，
S3 只负责把**结构保护的编辑语义**在命令层落定。

- 新增 `crates/scholium-app/src/page_editor/caret.rs`：定义 `Caret`、`Selection`
  以及 `Caret ↔ BlockPosition ↔ 投影字节` 的双向转换（已实现，8 项单测）。
- 新增 `crates/scholium-app/src/page_editor/command.rs`：`EditCommand`
  （插入文本、拆分块、合并块、删除范围、进入/退出公式、切换格式），
  每个命令在结构层求值后才投影成 markup。跨块操作在这一层有显式表示。
- `EditorState` 的 `anchor: usize` / `caret: usize` 换成 `selection: Selection`。
  删除 `focus_after_split/merge/replace` 三个启发式字段（[`state.rs`](../../crates/scholium-app/src/state.rs)），
  改按请求回声对账——这是 E1 在区域计划里的原始判据。
- 保持 `page_editor.rs` 及其子模块单文件 ≤ 600 行（[AGENT.md](../../AGENT.md) 门槛 + CI 脚本）。
  当前 `page_editor.rs` 464 行，新增逻辑必须落在子模块。
- 交付物：`caret.rs`、`command.rs`、`EditorState` 改造；`buffer.rs` 现有 shift 链保留但
  改为服务于几何映射而非光标权威。
- 判据：`cargo test --workspace` 全绿；审计契约**通过数不得低于 13**
  （S2 结束时应已覆盖结构语义，见 S3）；`page_editor` 不再有全局字节偏移字段；
  `focus_after_*` 三字段删除且 `session/tests.rs` 中相关断言改写为回声对账。
- 可回退点：本步是分支上的独立提交，回归时整体 revert。

### S3：结构编辑语义在命令层落定（关闭 a01–a06、b01、b10）

依赖 S2 建立的命令层（`command.rs` 在 S2 已引入）。定义并实现以下语义，每条一个测试：

| 操作 | 期望语义 |
|---|---|
| 行内公式右缘回车（a01、b01） | 公式完整保留，新块在公式**之后** |
| 独立公式右缘回车（a02） | 同上；公式标记与内容逐字不变 |
| 公式**内部**回车（a03） | 明确二选一并写进 ADR：拆成两个公式，或整块拆块且公式不被破坏。**不允许**出现含 `$` 的 `Inline::Text` |
| 粗体内部回车（a04） | `*abcd*` 光标在 3 → `*ab*` + `*cd*`（格式跨段延续） |
| 公式尾退格（a05、b10） | 删除公式**内容**，不删定界符；不允许公式退化为文字 |
| 公式首 Delete（a06） | 同上，方向对称 |

- 交付物：`input.rs` 的 `insert`/`key_event` 改为派发到 `command.rs` 的命令；
  测试补进 `session/usability_audit/editing.rs`（契约用例保持 opt-in）
  与 `page_editor/tests.rs`（常规回归）。
- 判据：a01–a06、b01、b10 从 FAILED 转 ok；a11（普通分段合并往返）等 13 项已通过用例**不回退**。
- 反例要求：每个语义都要有一条"结构不被破坏"的负向断言（不得出现含 `$`/`*` 的 `Inline::Text`），
  这正是报告 0046 验证实际后果的口径。

### S4：几何按 revision 解释（关闭 b06–b08、b13）

依赖 S2。当前 [`page_editor.rs`](../../crates/scholium-app/src/page_editor.rs) 的 `page_cells`
用**当前**快照的块长度和 UTF-8 边界解释**旧 revision** 的字形偏移，随后再重放全局 shift。

- 几何记录产生它的 revision；旧坐标经该 revision 起的变更链**转换一次**。
- 映射不可靠（命中的是已被删除的端点、或跨了结构边界）时返回"无法定位"：
  **禁止**落到别的段落继续写入，也禁止用旧坐标驱动编辑请求。
- b13：同帧点击与键入必须不 panic。当前是长度 10 的字符串被访问到 byte 12
  （[`input.rs`](../../crates/scholium-app/src/page_editor/input.rs)）。这是**崩溃**，优先级等同 P1。
- 交付物：`page_editor.rs` 的 `page_cells` 重构为 revision 感知的映射模块（新文件，
  避免 `page_editor.rs` 超 600 行）。
- 判据：b06/b07/b08/b13 转 ok；b13 另加一条常规（非 opt-in）回归测试，
  崩溃修复不能只靠审计套件覆盖。

### S5：回显层不画 markup（关闭 b02、b03、b04、b05）

依赖 S2（不改回报显字符串，就无法既回显又不暴露 `$`）。

- `optimistic_line` 当前把规范 markup 直接交给 `layout_no_wrap`，所以页面显示 `$alpha$`、`*bold*`。
  改为按结构投影绘制：公式/粗体按**当前外观**回显，不画标记字符。
- b04/b05：需要旧行字形才能回显，因此空文档和新段落没有即时反馈。改为不依赖旧字形的
  过渡布局（活跃行在原生页面内即时排版），这也是报告 0046"活跃行的过渡布局必须理解正文和公式"的要求。
- 交付物：`optimistic_line` 重写 + 过渡布局模块。
- 判据：b02–b05 转 ok；R4 的原有判据（击键当帧可见）不回退。

### S6：最小动作撤销（关闭 a17）

依赖 S3（撤销的记录单位是语义操作）。当前 [`commands.rs`](../../crates/scholium-app/src/commands.rs)

- 判据：a17 转 ok；文本/结构变更可撤销重做；连续撤销跨编辑类型不串状态。

### S2 实测结果（2026-09-27）

`python3 scripts/audit-editor.py --native`，逐项对比报告 0046 的原始证据：

- 门禁 `format` / `size` / `clippy -D warnings` / `rustdoc` 全部 exit 0；
  `cargo test --workspace` 95 passed / 0 failed（基线 81 项）。
- 体验契约 13 → **16**，**零回归**；原生窗口 4 → **5**，**零回归**。
- 新通过：`a05`、`a06`（公式边界删除）、`b10`（有几何的公式尾退格）。
  原生 `formula-backspace`（内容损坏类）转通过。

**`a07` 的口径说明**：`a07`（粘贴普通标点等于键入）在报告 0046 基线即为 **FAILED**，
不是本轮引入。它在语义上与"粘贴按 markup 解析"冲突——键入需要转义 `*`/`_`/`\`，
粘贴需要原样解析结构。当前按"不静默损坏内容"优先保留 markup 粘贴，
`a07` 维持 FAILED 作为**待裁决的产品契约**（见下）。这不是把它豁免为 expected-failure，
而是它本就在失败清单里，且本轮没有让它变差。

**待裁决**：剪贴板到底该不该隐式解释结构（粘贴 `$x$` 得到公式，还是得到字面 `$x$`），
需要一条明确的产品规则并写进[体验规范](../EXPERIENCE.md)。当前实现选择 markup，
理由是转义会静默把公式降级成文本，属于报告 0046 判 Fail 的同一类损坏。

**裁决（2026-09-27，据既有规范）**：查阅[体验规范 §9 多格式粘贴](../EXPERIENCE.md)后，
现有规范已经给出答案——"普通粘贴优先使用剪贴板的 HTML/MathML 等**结构格式**，退化到纯文本；
'粘贴为'允许显式选择"。即**结构感知粘贴是规范要求的行为**，plain-text 退化只是兜底。

因此：

- 粘贴按 markup 解释、`a07` 维持 FAILED 是**符合规范**的取舍，不是缺陷。
  `a07` 断言"粘贴普通标点必须等于逐字键入"，与 §9 的结构优先冲突；
  它作为**规范冲突的登记项**保留在失败清单，不做 expected-failure 豁免，也不为它牺牲内容完整性。
- 真正的缺口是 §9 尚未实现的其余部分：**HTML/MathML 结构格式读取**、
  **"粘贴为"显式选择**、以及"检测到源码时先显示目标结构预览与兼容状态再插入"。
  这些属于阶段 3 的格式交换范围，不在 E1 内。
- E1 只固化一条最小规则：**纯文本粘贴按编辑 markup 解释，不得静默把结构降级成字面字符**，
  且这条规则与其反例（`a07`）都留在审计清单里可追溯。

### S3 实测结果（2026-09-27）

`python3 scripts/audit-editor.py --native`，同样逐项对比报告 0046 的原始证据：

- 门禁 `format` / `size` / `clippy -D warnings` / `rustdoc` 全部 exit 0；
  `cargo test --workspace` 98 passed / 0 failed。
- 体验契约 16 → **21**，**零回归**；原生窗口 5 → **7**，**零回归**。
- 新通过：`a01`、`a02`、`a03`、`a04`、`b01`；原生 `inline-enter`、`display-enter` 转通过。

**根因不是拆分逻辑，而是范围端点。** 整块替换用 `Caret{inline: 0, offset: 0}` 作起点时，
`position_of` 会加上 `delimiter_start`，范围因此从 `$` **之后**开始，替换结果变成 `$$alpha$`
——开定界符被复制、公式被劈开，正好产生观测到的 `[Math(""), Text("alpha$")]`。
修复方式是引入 `RangeEdge{BlockStart, BlockEnd, At(Caret)}`：整块替换用真正的投影字节 0
与块尾，不再经过会被定界符平移的 caret。一处修正同时解决 a01/a03/a04/b01。

**`a02` 的右缘判定**：`$ alpha/2 $` 的填充空格存在**源串内部**，所以"caret 之后只剩空白"
在语义上就是右缘，公式应保持完整。该规则写进了代码注释并配回归测试；
Enter 落在真实内容之后（如 `$abc|cd$`）仍按 ADR 0031 拆成两个公式，规则不会过度适用。

**新增 3 项常规（非 opt-in）回归测试**，断言 ADR 0031 的负向铁律
"不得出现含 `$`/`*`/`_` 的 `Inline::Text`"：右缘回车、公式内回车拆两个、粗体跨段延续。
这类内容损坏修复从此进入 `cargo test` 门禁，不再只由 opt-in 审计脚本覆盖。

### S4 实测结果（2026-09-27）

- 门禁 `format` / `size` / `clippy -D warnings` / `rustdoc` 全部 exit 0；
  `cargo test --workspace` 99 passed / 0 failed。
- 体验契约 21 → **25**，**零回归**；原生窗口维持 **7/8**，已通过场景无一变红。
- 新通过：`b06`、`b07`、`b08`、`b13`。

**根因不是"没记 revision"，而是三个坐标系被混用。**
`buffer::global(snapshot, block, old_offset)` 把**旧 revision 的块内偏移**拿去**当前快照**
做 `is_char_boundary` 校验，**之后**再重放全局 shift——正是本计划点名要消除的组合。
三个坐标系必须分清：

1. `cell.input` 是**块内**偏移，属于**编译时**的块文本。该文本已不存在，只能平移，不能重新校验；
2. `edit_shifts` 是**全文拼接坐标**：块 1 内的编辑移动的是块 2 的 **base**，不动块 2 的内部偏移；
3. 字形**存活**当且仅当它覆盖的字节存活。

新实现 `render::map_cell_range()`：base 走全文链，块内偏移只走**落在该块内**的 shift，
再调 `buffer::map_forward`，`Side::Start`/`Side::End` 分别处理共享边界。
关键新增语义：**删除即无法定位**——偏移落在 `[shift.start, shift.old_end)` 时返回 `None`，
不复用 `map_forward` 的"塌缩到替换起点"。后者对光标正确，对**命中框**是错的：
它会让点击落到替换文本上，正是"静默写到错误位置"的来源。
`navigation::target_page` 原有同一处 bug，已改用同一函数。

**b13 硬性交付项已落实**：`page_editor::tests::stale_click_and_typing_in_one_frame_never_panics_and_keep_their_own_effects`
是普通 `#[test]`（以 `--list` 与 `--list --ignored` 双重证明在常规套件中、不在 ignored 集合），
覆盖"真实 Typst 字形 → 键入使几何陈旧 → 点击与键入同帧结算"的完整时序。
S2b 报告报备的缺口由此关闭：**崩溃修复不再只由 opt-in 审计脚本覆盖**。

### S5 实测结果（2026-09-27）

- 体验契约 25 → **30**，**零回归**（`b02`/`b03`/`b04`/`b05` 转通过，另附带修好 `a15`）。

**方案抉择（Lead 裁决）**：回显要按结构投影绘制，就必须拿到 `Vec<Inline>` 而非拼接字符串。
两条路：

- **(A) 在 `render.rs` 里从 `markup` 字符串反推结构** —— 需要第二个 markup 解析器
  （`scholium_document::parse_markup` 是私有的）。**否决**：AGENT.md 硬性约束 2
  「一个项目只能有一个权威模型」，两个解析器必然漂移，且漂移是静默的。
- **(B) 让命令层把求值时已经算出的结构一并留下** —— **采用**。
  `command.rs` 在 `split_block` 路径里本来就已经构造 `Vec<Inline>`（`head`/`tail`），
  之后只是 `markup()` 投影；把结构留下是**零成本、不新增权威**。

`markup` 继续作为 `BlockEdit::ReplaceRange` 的条件保留，`content` 只是**附加**产物，
两者**同源同一次求值**产生，不得事后重新解析。

**回显定位**：优先用当前 revision 的字形行；该块无可用字形时（空文档、新段落）
退到 `preview.anchors[block].start_y`。不变量：**anchors 只决定"画在哪里"**，
绝不驱动编辑请求，也不用于命中测试——那正是 S4 刚修掉的"旧几何当新"问题。

**`a15` 附带修好**：该用例（无几何时 Home/End 停留在本段而非跳整篇首尾）
不在原 E1 分步的任一步内，属实施者按"同一死区族"顺手修复，已如实登记于此。

## 实施中修正的两处既有假设

实施 S2 时发现本计划与 `caret.rs` 的两个隐含假设不成立，已修正：

1. **`Text` 内容在投影中被转义。** `scholium_model::markup` 对 [`Inline::Text`] 里的
   `$`、`*`、`_`、`\` 加反斜杠，而 `Math`/`Strong`/`Emphasis` 原样输出。
   最初的结构坐标实现按"存储字节 == 投影字节"计算，导致任何含字面 `$` 的段落偏移逐字符漂移，
   编辑会落到错误位置。现由 `projected_inline_offset`/`stored_offset` 双向换算，
   并以 `markup_offsets_match_the_real_projection` 断言
   `projected_len_block == markup().len()` 持续防止漂移。
2. **字节偏移不是 caret 的忠实地址空间。** 零宽节点（`Text("")`、`Math("")`）投影宽度为 0，
   其唯一 caret 与相邻节点的起始字节共用同一个偏移，任何反函数都无法区分。
   因此 `to_markup_byte`（caret → byte）是**精确、全定义、单调**的方向，用于构造编辑请求；
   `from_markup_byte`（byte → caret）只是**命中测试用的有损反函数**，
   承诺"返回块内合法 caret"而非双射。要求二者互逆曾是本计划的错误假设。

这两点都不改变 ADR 0031 的决策，只修正实现层的算术。

## 过程记录：写范围纪律

S2 实施中，Lead 与实现者曾**同时修改 `caret.rs`**，导致实现者撞上语法破损的中间态而无法编译。
这是写范围纪律的违反：`caret.rs` 属于 S2 核心，同一时刻只能有一个写者。
后果与纠正：Lead 停止非必要修改，回归文档与验证职责；
后续任何跨任务共用的文件，在任务描述里显式标注"单一写者"。
本计划的分步边界（`caret.rs` 核心 / `command.rs` + 接入 / 判据改写）应据此理解为
**互斥而非并行**的写范围。
若某条在新模型下确实无法保持，必须在开发日志里逐条列出并说明由后续哪一步补回，
而不是让通过数静默下降。

**E1 完成的定义**：32 项体验契约全部通过、8 个原生窗口场景全部通过、
`cargo test --workspace` 无回归、fmt/clippy/规模/rustdoc 全绿，且报告 0046 更新为
Pass 并保留原始失败证据作为修复溯源（[spikes 规则](../spikes/README.md)：不改写历史结论）。

注意 debug 构建的性能采样（报告 0046 的 c01）只作为**观测**，不设达标门槛；
E1 是正确性改造，不承诺性能改善，也不得因此恶化。

## 不做什么

- 不做完整 TreeCursor/固定槽位与 `docs/modules/document.md` 的目标态；那需要
  `Inline` 从扁平 `Vec` 升级为带槽位 schema 的节点树，属更大立项。
- 不改权威模型、不加第二可写副本（[硬性约束 2](../../AGENT.md)）。
- 不引入 JS/TS、WebView、npm（[硬性约束 10](../../AGENT.md)）。
- 不在本计划内做 R2 字体打包、R5 矢量渲染、E5 增量重排。
- 不搬运 `../mogan` 源码（[硬性约束 1](../../AGENT.md)）。
- 不把审计用例改成 expected-failure；失败是未满足的契约（报告 0046 已定）。

## 与区域计划执行序的关系
