# 产品定义

## 1. 产品定位

Scholium 是面向论文、技术文档和研究笔记的本地优先协作编辑器。默认体验是即时排版的结构化
编辑，但用户随时可以进入项目语言（Typst 或 LaTeX）以及 Markdown、BibTeX 的源码模式。

它不是传统“左侧源码、右侧预览”的 IDE，也不是只能导出私有格式的封闭 WYSIWYG。产品的核心价值
是让不想维护排版源码的人获得高效结构编辑，让熟悉源码的人仍能精确控制，并让两类用户在同一份
文档上协作。

### 技术实现约束

应用采用 Rust 原生桌面路线，必要时混用 C/C++/Zig，不依赖 npm、JavaScript/TypeScript 编辑器或 WebView。
Iced → GPUI → C++ EUI-NEO → Slint 或 egui 是验证顺序，不是已完成的选型。结构数学与源码工作台均须通过真实编辑验收。
HTML/MathML 导入导出、文档中的 LaTeX/Typst 语言仍保留；它们不等于应用 UI 技术栈。

## 2. 项目语言与工作形态

每个项目在创建或导入时确定**项目语言**：Typst 或 LaTeX。两种语言由两个独立的编辑内核承担，
共享窗口、命令、存储、历史、协作与构建沙箱，但不共享文档模型，也不在同一项目内混用
（[ADR 0041](adr/ADR-0041-separate-latex-typst-kernels.md)）。Markdown 与 BibTeX 是项目内资源，不改变项目语言。

### Typst 项目

- **原生结构项目**：语义文档图是权威内容，可视化编辑能力完整，Typst 同时负责交互预览与最终输出。
  源码修改解析回语义图；尚未理解的内容作为 Raw 保留，不能假装已成功排版。项目正文存为版本化开放
  schema，随时可完整导出。适合新建文档、团队协作和希望获得完整结构体验的用户。
- **`.typ` 源码项目**：源文件是权威内容。源码工作台完整可用；可视化视图只在能安全 round-trip 的区域
  启用写操作，未知函数以源码岛显示。可显式“转换为原生结构项目”，转换前必须预览兼容报告。

### LaTeX 项目

`.tex` 源文件是权威内容。源码工作台完整可用，预览由项目自身的 LaTeX 引擎产生：LuaLaTeX 项目按段落
实时重排，其他引擎以后台整编结果作为预览并标明延迟。页面与源码双向定位，诊断回链到源码位置。
适合导入现有论文、模板和复杂宏包项目。

一个项目在同一时刻只有一种权威模型和一种项目语言。切换权威模型或项目语言都是带报告的项目迁移：
「转换为…」生成新项目，原项目保留，不是切换标签页。不能谎称任意 LaTeX/Typst 源码都可无损互相转换。

## 3. 默认编辑体验

- 打开原生项目首先看到即时排版页面，不需要先配置编译器。
- 光标始终有模式与焦点：文本、数学、源码；焦点是最内层结构环境。
- 模式工具栏展示当前输入语言；焦点工具栏展示当前结构的属性与变体。
- `\` 进入统一命令模式，支持 LaTeX 熟悉命令、Scholium 命令和项目宏补全。
- `$` 进入行内数学；独立公式、多行公式、矩阵和表格均有键盘入口。
- Tab 用于命令补全、空槽导航和符号循环，具体行为由上下文决定且在 UI 明示。
- 图片、表格、引用、定理和章节可直接操作，同时始终能查看它们对应的源表示。
- 源码模式不是只读调试窗，可直接编辑、诊断、补全、保存和协作。

完整交互见 [体验设计](EXPERIENCE.md)。

## 4. 编译与预览

- 预览与最终输出使用项目语言的同一引擎，不用另一种语言的引擎代替预览。
- Typst 项目经语义图或源码由 Typst 连续排版；交互预览与最终构建共享同一后端。
- LuaLaTeX 项目由常驻引擎实时重排被编辑的段落，全局分页、浮动体、目录与引用由后台整编更新；
  实时结果与整编不一致时以整编为准。pdfLaTeX/XeLaTeX 项目以后台整编作为预览。实时引擎选型待评估，
  见 [LaTeX 工作区计划](plan/LATEX_WORKSPACE.md)。
- UI 始终标明当前后端、排版是否为最新，以及实时/整编来源；有未解决的模板、分页或引用问题时阻止正式输出。
- 另一种语言的输出只经导出产生：生成目标源码与转换报告，由目标工具链构建并验证。

## 5. 核心工作流

### 新建

用户先选择项目语言，再选择形态：Typst（原生结构或 `.typ` 源码）或 LaTeX（`.tex` 源码）。默认推荐 Typst
原生结构项目，并选择论文、书籍、笔记等语义模板。

### 导入

选择文件或目录后先生成依赖与兼容报告。用户可以原地按源码项目打开，也可以转换为原生结构项目。
未知命令、动态路径、Raw 节点和预计排版差异必须在转换前展示。

### 结构编辑

正文、公式、列表、表格、图片、定理、引用等直接在页面中编辑。工具栏、快捷键和命令模式最终都
生成同一种 SemanticEdit，经历史和协作通道提交。

### 源码编辑

用户可打开完整 Source Studio，或对当前焦点使用“编辑源码片段”。原生项目的源码提交经过 parse、
project、diff、compatibility preview，再成为语义动作；源码项目直接修改权威文本并刷新结构投影或预览。

源码语言就是项目语言，团队成员编辑同一种语言，同语言可多人同时编辑并经 CRDT 合并。离线仍可编辑，
重连后按普通协作合并。

### 打开、保存与另存为

直接打开 `.tex`、`.typ` 文件或项目目录，按扩展名与入口确定项目语言，原格式保存；语法错误和缺编译器
不阻止保存。原生项目保存语义正文、资源和未提交草稿。跨格式“另存为”生成新的目标项目，处理依赖并展示
报告，成功后可继续编辑目标，原项目保留。导出生成副本，不改变当前项目及其语言。
文件操作与报告见 [项目语言、跨格式转换与文件操作](MIXED_SOURCE_EDITING.md)。

### 格式转换

LaTeX ↔ Typst 使用 `源 CST → 转换 IR → 目标生成器`，是一次性迁移或导出；不能原生转换的内容按 Raw
保留原文并标为 Degraded 或阻止导出，不在目标项目中执行另一种语言。转换报告逐节点记录语义保真度与可编辑性；
不能用“已保留源码”代替“已完成目标输出”。默认不允许未确认的 Dropped。

### 历史与协作

普通撤销只撤当前用户动作；时间线支持 checkpoint、任意 revert、分叉、cherry-pick 与 merge。
结构操作和源码操作使用同一 Action 模型，协作者可同时处于不同视图。

## 6. 首发范围

"首发"指阶段 0–6 全部出口条件通过后的首次公开版本，不是阶段 1 的最小闭环；各项能力所属阶段见
[路线图](plan/ROADMAP.md)。以下是 v1 的完整范围：

- 原生结构项目的文本、数学、章节、列表、定理、图片、表格、代码、脚注、引用。
- 文本/数学/命令三种输入模式，焦点工具栏、符号循环、结构导航与取消环境。
- Typst 项目：Typst 交互预览即最终输出，Typst 源码工作台。
- LaTeX 项目：LaTeX 源码工作台，同引擎预览（LuaLaTeX 实时段落重排或后台整编），源码 ↔ 页面定位与诊断，
  命令/引用补全与大纲；页面内编辑正文与公式按 [LaTeX 工作区计划](plan/LATEX_WORKSPACE.md) L3 的 ADR 裁决范围提供。
- `.tex`、`.typ`、`.md`、`.bib` 源码项目与导入报告。
- LaTeX/Typst 常用论文子集的一次性转换，以及 PDF、HTML、Markdown、纯文本导出。
- 原格式保存，两种语言的源码项目/PDF 导出各自经目标工具链验证。
- 本地恢复、非线性历史和三人以上协作。

## 7. 不承诺

- 任意 LaTeX 宏包和任意 Typst 函数都能转换为可视化结构。
- 在同一项目内混用 LaTeX 与 Typst，或在项目内切换编辑语言（已按 ADR 0041 推迟）。
- LaTeX 项目的页面内直接编辑与 Typst 原生结构项目同等完整。
- 任意 LaTeX/Typst 程序都能直接变为另一种语言。
- 首个核心编辑版本实现 AI、CAS、绘图、幻灯片、移动端或任意插件执行。

后续扩展路线包含可选 Pi agent 接入、供其他 agent 调用的 MCP server，以及 WIT/WASM 插件；
交付依赖与出口见 [路线图](plan/ROADMAP.md)，不改变首个核心编辑版本的门槛。

## 8. 成功指标

- 新用户不安装 TeX 即可新建并即时编辑原生文档。
- 熟练用户能在 `\` 命令、键盘结构操作和源码模式之间无缝切换。
- 原生项目的受支持节点完成 `语义图 → LaTeX/Typst → 语义图` 语义 round-trip。
- 源码项目未编辑区域字节不变，未知语法不丢失。
- Typst 交互预览输入路径 p95 不阻塞 16ms 帧；LaTeX 实时预览与整编始终异步、可取消，不阻塞输入。
- 跨格式转换对每个节点给出可解释状态，没有静默 Dropped。
- 远端动作穿插后，本地撤销不删除其他参与者内容。
- LaTeX 项目的实时预览与整编结果逐字形一致；不一致时显示整编结果并说明原因。
- 未提交或语法错误的源码草稿崩溃后可恢复；占位预览不能通过正式输出门禁。

## WASM 目标

优先保证 Rust 核心可以用于 WASM，并探索浏览器打开、编辑、保存 `.tex` / `.typ` 项目。完整浏览器功能不作为已确认首发承诺：本地 LaTeX 编译、目录访问和持久化受宿主限制，见[WASM 能力矩阵](plan/WASM.md)。桌面保持原生技术栈。远程构建由用户显式选择，不能静默上传；项目语言固定与预览同引擎的要求不因宿主改变。
