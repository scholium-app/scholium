# 产品定义

## 1. 产品定位

Scholium 是面向论文、技术文档和研究笔记的本地优先协作编辑器。默认体验是即时排版的结构化
编辑，但用户随时可以进入 LaTeX、Typst、Markdown 或 BibTeX 源码模式。

它不是传统“左侧源码、右侧预览”的 IDE，也不是只能导出私有格式的封闭 WYSIWYG。产品的核心价值
是让不想维护排版源码的人获得高效结构编辑，让熟悉源码的人仍能精确控制，并让两类用户在同一份
文档上协作。

### 技术实现约束

应用采用 Rust 原生桌面路线，必要时混用 C/C++/Zig，不依赖 npm、JavaScript/TypeScript 编辑器或 WebView。
Iced → GPUI → C++ EUI-NEO → Slint 或 egui 是验证顺序，不是已完成的选型。结构数学与源码工作台均须通过真实编辑验收。
HTML/MathML 导入导出、文档中的 LaTeX/Typst 语言仍保留；它们不等于应用 UI 技术栈。

## 2. 两种工作形态

### 原生结构项目

语义文档图是权威内容。可视化编辑能力完整，Typst 默认负责低延迟交互预览。源码编辑语言、默认排版
后端和每次导出目标独立选择。源码修改解析回语义图；需继续执行的异语言内容成为 ForeignSource，
尚未理解或尚未配置执行环境的内容作为 Raw 保留，不能假装已成功排版。

适合新建文档、团队协作和希望获得完整结构体验的用户。项目正文存为版本化开放 schema，随时可
完整导出；不能谎称任意 LaTeX/Typst 源码都可无损双向转换。

### 源码项目

现有 `.tex`、`.typ`、`.md`、`.bib` 文件是权威内容。源码工作台完整可用；系统解析出结构投影，
可视化视图只在能安全 round-trip 的区域启用写操作，未知宏/函数以源码岛显示。

适合导入现有论文、模板和复杂宏包项目。用户可显式“转换为原生结构项目”以获得更完整的可视化体验，
转换前必须预览兼容报告。

一个项目在同一时刻只有一种权威模型。切换权威模型是带报告、可撤回的项目迁移，不是切换标签页。

两类项目都支持 LaTeX/Typst 混用。原生项目在语义正文中保存异语言组件；源码项目在主语言入口中用
声明式绑定引用独立的另一语言源文件。一个权威模型可以包含多种语言，不维护两份可任意互相覆盖的整篇正文。

## 3. 默认编辑体验

- 打开原生项目首先看到即时排版页面，不需要先配置编译器。
- 光标始终有模式与焦点：文本、数学、源码；焦点是最内层结构环境。
- 模式工具栏展示当前输入语言；焦点工具栏展示当前结构的属性与变体。
- `\` 进入统一命令模式，支持 LaTeX 熟悉命令、Scholium 命令和项目宏补全。
- `$` 进入行内数学；独立公式、多行公式、矩阵和表格均有键盘入口。
- Tab 用于命令补全、空槽导航和符号循环，具体行为由上下文决定且在 UI 明示。
- 图片、表格、引用、定理和章节可直接操作，同时始终能查看它们对应的源表示。
- 源码模式不是只读调试窗，可直接编辑、诊断、补全、保存和协作。

完整交互见 [体验设计](EXPERIENCE.md)。

## 4. 编译与预览

- 原生结构项目默认经语义图生成 Typst，提供快速连续预览。
- 用户可随时执行 LaTeX 验证构建，检查最终 LaTeX 输出、模板和宏包兼容性。
- 选择 LaTeX 为发布目标时，Typst 预览明确标注“快速预览”，最终输出以 LaTeX 构建为准。
- 选择 Typst 为发布目标时，交互预览与最终构建共享同一后端。
- 源码项目使用其原生后端构建；不会悄悄把 LaTeX 项目用 Typst 排版后冒充最终结果。
- 限制的是团队正在编辑的源码语言，不限制编译器并行。混合构建按依赖关系调用两种引擎，独立任务可并行。
- 两种后端均可作为最终输出目标；混合内容经目标原生生成、异语言编译嵌入或显式桥接后输出。
  有未解决的模板、分页、宏作用域或引用问题时阻止正式输出，不能把占位预览标成最终结果。

## 5. 核心工作流

### 新建

用户选择原生结构、LaTeX、Typst 或 Markdown 项目。默认推荐原生结构项目，并选择论文、书籍、笔记
等语义模板；模板与排版后端分离。

### 导入

选择文件或目录后先生成依赖与兼容报告。用户可以原地按源码项目打开，也可以转换为原生结构项目。
未知命令、动态路径、Raw 节点和预计排版差异必须在转换前展示。

### 结构编辑

正文、公式、列表、表格、图片、定理、引用等直接在页面中编辑。工具栏、快捷键和命令模式最终都
生成同一种 SemanticEdit，经历史和协作通道提交。

### 源码编辑

用户可打开完整 Source Studio，或对当前焦点使用“编辑源码片段”。原生项目的源码提交经过 parse、
project、diff、compatibility preview，再成为语义动作；源码项目直接修改权威文本并刷新结构投影。

同一共享项目分支中，整个团队同一时刻只能编辑 LaTeX 或 Typst 中的一种源码语言，同语言可多人同时编辑。
另一语言可查看、复制和编译；开始编辑前须完成团队语言切换。首发采用项目分支级范围，避免多个入口共享宏、
模板或文献时绕过同一文档的限制。视觉编辑可并行，但修改异语言原文、宏和模板的操作也受同一规则约束。
离线仍可编辑；无法取得团队写入许可的源码修改存入本地草稿或独立分支，重连后明确合入，不能自动回灌。

### 打开、保存与另存为

直接打开 `.tex`、`.typ` 文件或项目目录，两种格式都可原格式保存；语法错误和缺编译器不阻止保存。
原生项目保存语义正文、混合源码、依赖绑定和未提交草稿。跨格式“另存为”生成新的目标项目，处理依赖并展示
报告，成功后可继续编辑目标，原项目保留。导出生成副本，不切换当前项目或团队编辑语言。

标准单文件不能独自携带任意混合工程；跨语言源码、资源、构建说明和必要元数据随项目目录或归档包交付。
可移植性和保真程度必须分别说明，见 [混合源码与团队编辑](MIXED_SOURCE_EDITING.md)。

### 格式转换

LaTeX ↔ Typst 使用 `源 CST → 转换 IR → 目标生成器`；不能原生转换的内容进入保留原文的混合构建路线。
转换报告分别记录语义保真度、可编辑性、渲染途径和可移植性；不能用“已保留源码”代替“已完成目标输出”。
默认不允许未确认的 Dropped，正式构建拒绝 unresolved 内容。

### 历史与协作

普通撤销只撤当前用户动作；时间线支持 checkpoint、任意 revert、分叉、cherry-pick 与 merge。
结构操作和源码操作使用同一 Action 模型，协作者可同时处于不同视图。

## 6. 首发范围

"首发"指阶段 0–6 全部出口条件通过后的首次公开版本，不是阶段 1 的最小闭环；各项能力所属阶段见
[路线图](plan/ROADMAP.md)。以下是 v1 的完整范围：

- 原生结构项目的文本、数学、章节、列表、定理、图片、表格、代码、脚注、引用。
- 文本/数学/命令三种输入模式，焦点工具栏、符号循环、结构导航与取消环境。
- Typst 快速预览，Typst 与 LaTeX 源码工作台，LaTeX 验证构建。
- `.tex`、`.typ`、`.md`、`.bib` 源码项目与导入报告。
- LaTeX/Typst 常用论文子集双向转换，以及 PDF、HTML、Markdown、纯文本导出。
- LaTeX/Typst 混用覆盖正文、公式、图表、自定义宏、模板及跨组件引用；按能力矩阵分阶段验证，不能以只支持公式
  或图片嵌入宣称混用完成。精确分页、可访问性和模板差异须报告；不支持的组合阻止相应正式输出。
- 团队单一活动源码语言、可靠切换、原格式保存、混合项目重开，以及两种目标的源码项目/PDF 导出。
- 本地恢复、非线性历史和三人以上协作。

## 7. 不承诺

- 任意 LaTeX 宏包和任意 Typst 函数都能转换为可视化结构。
- Typst 快速预览与 LaTeX 最终 PDF 像素一致。
- 用户同时编辑同一文档的 LaTeX 与 Typst 两份权威源码。
- 团队成员在同一共享分支同时编辑不同语言的源码；独立分支不在此限制内，合并须重新校验。
- 任意 LaTeX/Typst 程序都能直接变为另一种语言，或标准单文件能无依赖运行任意混合内容。
- 首个核心编辑版本实现 AI、CAS、绘图、幻灯片、移动端或任意插件执行。

后续扩展路线包含可选 Pi agent 接入、供其他 agent 调用的 MCP server，以及 WIT/WASM 插件；
交付依赖与出口见 [路线图](plan/ROADMAP.md)，不改变首个核心编辑版本的门槛。

## 8. 成功指标

- 新用户不安装 TeX 即可新建并即时编辑原生文档。
- 熟练用户能在 `\` 命令、键盘结构操作和源码模式之间无缝切换。
- 原生项目的受支持节点完成 `语义图 → LaTeX/Typst → 语义图` 语义 round-trip。
- 源码项目未编辑区域字节不变，未知语法不丢失。
- Typst 交互预览输入路径 p95 不阻塞 16ms 帧；LaTeX 构建始终异步、可取消。
- 跨格式转换对每个节点给出可解释状态，没有静默 Dropped。
- 远端动作穿插后，本地撤销不删除其他参与者内容。
- 两人竞争切换、旧客户端迟到提交和离线重连不会造成两个源码语言同时在共享分支可写。
- 包含正文、宏、模板和交叉引用的混合项目可保存重开，分别生成经验证的 LaTeX/Typst 目标项目与 PDF。
- 未提交或语法错误的源码草稿崩溃后可恢复；占位预览不能通过正式输出门禁。

## WASM 目标

优先保证 Rust 核心可以用于 WASM，并探索浏览器打开、编辑、保存 `.tex` / `.typ` 与混合包。完整浏览器功能不作为已确认首发承诺：本地 LaTeX 编译、目录访问和持久化受宿主限制，见[WASM 能力矩阵](plan/WASM.md)。桌面保持原生技术栈。远程构建由用户显式选择，不能静默上传；团队源码语言门禁与两种最终目标输出要求不因宿主改变。
