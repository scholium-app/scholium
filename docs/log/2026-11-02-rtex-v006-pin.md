## E1 失败的具体原因

`allow-wildcard-paths = true` 不豁免可发布 crate 的无版本 path 依赖。上游三个 manifest 仍有以下引用：

| crate | 依赖 |
|---|---|
| rtex-cli | rtex-core、rtex-dl、rtex-verify |
| rtex-core | rtex-dl |
| rtex-verify | rtex-dl |

与[第一轮](2026-10-30-rtex-evaluation.md#e1-许可与依赖)相同，这些是内部依赖元数据问题，
但仍是绑定策略的真实失败，没有用临时 manifest 补丁绕过。
`lopdf` 已从 0.36.0 升级到 0.42.0，本次公告输出不再报告 `RUSTSEC-2026-0187`。
剩余的 `ttf-parser 0.25.1` 除了经 `rtex-verify` 直接引入，也经 `lopdf 0.42.0` 引入
`rtex-core` 与 `rtex-verify`；因此不能称为仅验证工具的问题。公告指出没有安全升级版本，未声称发现了新的可利用漏洞。
