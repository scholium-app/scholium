bans 的内部 path wildcard 及未过滤 advisories 记录但不阻断**。未改 `deny.toml`，未过滤公告。

- licenses：0 errors、8 条未用 allowance 警告、120 notes；sources：0 errors / warnings。
- bans：3 条 wildcard 错误，rtex-cli → rtex-core/rtex-dl/rtex-verify，rtex-core → rtex-dl，rtex-verify → rtex-dl。
  都是 rtex 自身 workspace crate 的无版本 path 依赖，与第一轮同类；Scholium 只在沙箱内启动 rtex 子进程，不链接它。
- advisories：总数 **2 → 1**；lopdf 0.42.0 不再报告旧 `RUSTSEC-2026-0187`。
  剩余 `RUSTSEC-2026-0192` 是 `ttf-parser 0.25.1` 不维护通知；本应用的 `Cargo.lock`、`cargo tree -i ttf-parser`
  也显示 Typst/fontdb/rustybuzz 使用同版。因此列为**项目级依赖跟进**，不是 rtex pin 阻断，也不据此声称发现新可利用漏洞。

## E8：上游超时，无宿主单次编译看门狗

v0.0.6 `rtex serve` CLI **没有** `pass_timeout` flag，默认 300 秒；上游 Rust `SessionConfig.pass_timeout`
及 C/JSON `pass_timeout_ms` 有此字段。为配置 8 秒，使用本仓库原创的
[`pass-config.rs`](../../spikes/rtex-eval/pass-config.rs) 作为**仓库外评估进程**：将精确 tag 的源码放入外部目录，
只在其 rtex-cli manifest 追加 binary target，以原封不动的 upstream Cargo.lock 构建；该进程只设置 upstream config、
转发命令和事件，不修改引擎实现，不进入 Scholium 链接图。构建方法在 README。
主 clone 在实验期间恢复为未修改状态，并完成原版 CLI release rebuild。

配置与锁文件 hash、外部目标变更见 [build-provenance.json](evidence/rtex-v006-pin/e8-final/build-provenance.json)。
完整配置矩阵见 [e8-final 汇总](evidence/rtex-v006-pin/e8-final/e8-summary-t34-v006-e8-final.json)；
显式 SIGKILL 与超时对照见 [pass-faults.json](evidence/rtex-v006-pin/e8-pass-final/pass-faults.json)。
普通未修改 CLI 的 [独立矩阵](evidence/rtex-v006-pin/e8-cli-warm/e8-summary-t34-v006-e8-cli-warm.json)
也覆盖了 malformed 与 engine/preamble/serve 故障，避免把评估协议层当作原 CLI 的输入拒绝证据。

| 故障 | 配置矩阵观察 | 判定 / 宿主职责 |
|---|---|---|
| background SIGKILL / timeout 独立对照 | Failed（signal 9）/ Failed（8006 ms），修复后 0.510 / 0.414 s 收敛 | 两项都由事件证据判定通过 |
| live engine SIGKILL | Restarting 0.009 s，Ready 0.638 s；在途 edit 无自己的更新；后续输入与布局成功 | 恢复通过；宿主在 Restarting/Failed 后补请求布局 |
| live + background 无限循环 | rtex 自身 live watchdog 在 5.169 s 重启，5.516 s Ready；后台 8008 ms 后 Failed，诊断明确 8 秒上限 | 不依赖宿主 pass watchdog；其他段 edit 未收到独立更新，须记录并补布局 |
| 修复循环 | 删除循环在 8.170 s；修复后 5.72 s 收敛 | 后台失败不能报 Ok；源 revision 后续收敛 |
| 缺宏包 | Starting → Failed 一次，修复前约 18 秒无重启循环；修复后 live 0.836 s、布局恢复 | 通过；故障期间 body edit 无更新，宿主不能静默等它 |
| undefined command | CompiledWithErrors；修复后 live 1.192 s、布局 1.385 s 恢复 | 通过，保留诊断 |
| 反向/越界/负偏移/未知文件/UTF-8 中间/项目外路径/坏 JSON/未知命令 | 11/11 error + server alive，0 外部写入；普通 CLI 也 11/11 | 通过，宿主 offset/path 校验仍保留作纵深防御 |
| serve SIGKILL | EOF 0.001 s、退出 137、无残留；暖缓存重启首次布局 1.430 / 2.119 s | heartbeat + EOF/exit 检测与整会话重启仍由宿主做 |

`restart_tmpfs` 是旧结果键名：本轮驱动已统一预热缓存，两项都是暖缓存启动，不声称冷启动成绩。
`recovered_live_s≈15` 包含驱动固定 drain 15 秒后才继续输入，实际 engine Ready 取表中事件时刻。
此前默认 300 秒 CLI 全矩阵只作本地参考，不将 RLIMIT_CPU 30 秒误称 `pass_timeout=8s`。
测试先覆盖“被杀却报 Ok 不得通过”“超时必须 Failed 且能恢复”“每条畸形输入必须 error+alive”；
后来新增普通 CLI 不得虚报显式超时的失败测试，再修复 driver 参数/标注。

暖收敛 2.199 / 9.310 s（此前 2.2 / 9.5 s），峰值 627.2 / 1036.6 MiB；100 页 burst 栅格最大 177.216 ms，
仍有布局装入导致的尾延迟。真实窗口纹理上传/呈现延迟继续留 L1，不用本次 Python 宿主流水线代替。
