# 开发日志与过程记录

> **时效语义：过去时。** 本目录只收「某个时刻做到哪一步」的记录，只追加、不删改既有段落，
> **不得作为实现依据**。要当前结论去 `docs/spikes/SPK-0012-exit-criteria.md`；要要求去 `docs/` 与 `docs/plan/`。

## 边界

| 体裁 | 时态 | 去处 |
|---|---|---|
| 设计规范 | 现在时：系统应该怎样 | `docs/` 顶层与 `docs/modules/` |
| 计划 | 将来时：要做什么、什么算通过 | `docs/plan/` |
| **开发日志** | **过去时：做到哪了** | **本目录** |
| 阶段 0 否决性验证证据 | 可复现的实验结论 | `docs/spikes/`（只收对应路线图阶段 0 条目的 Pass/Fail/Blocked 报告） |
| 第 1 阶段起的实现记录与其证据 | 过去时 | 本目录；证据放 `evidence/<topic>/` |
| 裁决 | 已定 | `docs/adr/` |
| 废弃原型 | 已弃 | `docs/archive/` |
| 外部资料 | 参考 | `docs/research/` |

本目录与 `docs/spikes/` 的分工：**`spikes/` 收阶段 0 的否决性验证证据**（锁定版本、真实平台、可复现命令、
原始数据，结论只能是 Pass/Fail/Blocked 且须链接自路线图）；**本目录收其余的“叙述”**——进度、实现记录、
日期结论。产品实现不写成 spike 报告。

## 命名与证据

- 新日志命名为 `YYYY-MM-DD-<topic>.md`；目录顺序即时间顺序。新日志**不得编辑本 README**，也不得追加到任何共享清单。
- 日志自己的截图、原始日志、指纹放在 `evidence/<topic>/`（`<topic>` 即日志文件名去掉日期）；`assets/` 为早期日志的图片。
- 本节之下的清单是迁移前已存在的无日期旧日志，一次性列出，之后不再更新。
